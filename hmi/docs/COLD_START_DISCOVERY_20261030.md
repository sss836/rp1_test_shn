# 未使能冷启动扫描：等待预算与反馈确认修正

日期：2026-10-30。状态：修复源码与隔离回归完成，未打包、未安装、未进行实机验收。

## 问题、证据与根因边界

此前 `FactoryController._confirm_motor_feedback()` 对发现、使能、故障复位共用 `min(1.0, stale_seconds)` 确认窗口，要求每台电机的反馈时间至少推进两次。冷启动中有设备晚于该窗口才开始回应时，即使之后持续回复，也会报 `fresh feedback timeout`。

隔离假设备已复现启动 2.2 秒后才回应的场景，修正后能在有限扫描窗口内完成确认。尚未取得现场上电时间、设备首帧时间及原始报文，因此“现场一定是冷启动慢”“断电再开因为电机热过一轮而更快”仍是推断，不是本次确认的根因。

用户截图显示 can3 对应左臂、can2 对应右臂；can3 的 ID 2/3/4 显示 error_id=7，温度分别约 33/33/34°C。它并非只有 can3#3 扫描超时的截图。显示故障码、新鲜性判定与未收到足够反馈要分别核对；截图中的反馈年龄 0.000 不能替代原始收帧证据，尤其旧安装版还存在[先前软件审计](LRO_FEEDBACK_SOFTWARE_AUDIT_20261030.md)中的问题。

## 已实现行为

| 阶段 | 总等待预算 | 通过条件及行为 |
| --- | --- | --- |
| 未使能扫描 | 默认 5 秒，可配置为大于 0 且不超过 10 秒的有限值 | 每台电机至少两次真正推进的反馈，最后反馈仍在原有新鲜期限内；重复请求状态，不清错、不使能 |
| 使能前确认 | 原 `min(1.0, stale_seconds)` | 原有两次新反馈、非零故障拒绝、位置检查保留 |
| 使能后确认 | 原 `min(1.0, stale_seconds)` | 原有一次新反馈及位置检查保留，之后才允许位置保持 |
| 显式故障复位前后 | 原 `min(1.0, stale_seconds)` | 保留人工复位、每请求只清错一次、复位后两次新反馈且 error_id=0 |
| 正式运行中的失效判断 | 原值 | 没有放宽反馈失效门限、控制心跳或租约心跳 |

扫描请求之间等待 50 毫秒，另加状态读取本身耗时；硬件后端现有单轮反馈查询逻辑预算 30 毫秒未改。两次反馈之间若已跨过原有 stale_seconds，旧确认计数会清零；某节点早期回过两次、随后掉线，也不能靠历史次数通过全员确认。

等待通过同一个停止事件实现，不会每轮创建线程或 Qt 对象；失能/断开请求可中断等待。原生 SDK 调用仍可能阻塞，中断在调用边界生效；5 秒和 10 秒上限是逻辑预算，不是电气停机或实时硬中断保证。

扫描在同一通信会话内重查状态，不会自动反复关闭/重开驱动、重新上电、复位故障或发送使能。失败仍执行原有故障处理和整组失能尝试；通信故障时，发送失能成功与否仍须靠实际反馈核实。

## 状态与失败恢复

```text
已连接 CAN、未使能
  → 打开电机通信
  → 有限等待全员新反馈
      → 全部确认：标记 motors_discovered=True，仍未使能
      → 超时/读取失败/中断：FAULT，motors_discovered=False
          保留接收数据与诊断，禁止把“传输已打开”显示成“全员已发现”
```

扫描允许读取非零故障码用于诊断；这只表示通信扫描完成，不等于驱动健康。error_id=7 继续显示，不会被延长等待清除，也不能进入后续使能。真实的驱动器故障仍需按匹配协议与原始报文核实。

扫描失败后，在现场状态明确的前提下先正常断开电机连接，再连接 CAN/重新扫描即可；整柜断电不是软件流程的必选步骤。故障复位仍是独立的人工操作，不能拿重新扫描代替清错确认。

## 配置与日志

有效工位 YAML 可设置：

```yaml
factory_hmi:
  discovery:
    timeout_s: 5.0
```

该字段独立于 `factory_hmi.faults.stale_seconds`，不要为延长冷启动扫描而提高运行中的失效门限。

日志只记录确认开始、成功或超时，不在每一轮重查中刷屏。超时示例：

```text
motor discovery: fresh feedback timeout: motor_ids=3; elapsed_s=5.000; pending=can3#3[left_shoulder_yaw_joint](0/2,age_s=none)
```

`motor_ids` 保留旧格式供兼容解析；新增 pending 用总线、ID、关节和次数区分跨总线同 ID。`age_s=none` 表示尚无有效反馈时间，不把缓存零值当成设备回应。

## 验证与边界

最终定向回归：**168 项测试、35 项子测试通过**，1 项既有 Starlette/AnyIO 弃用警告。测试包括冷启动、故障恢复、界面、客户端、控制器、网关、服务生命周期和长期运行保护的隔离用例。

重点覆盖：2.2 秒后才启动的节点能完成扫描；完全无回复、一帧后冻结、早期确认后掉线不能通过；故障 7 不会自动清除且阻止使能；使能前仍在原有 1 秒以内的预算失败；扫描等待中网关租约心跳可回应，失能请求可中断。

扩大回归初次有一项 CSV 收尾测试失败：其租约为 150ms，当前回放按已有实现完成 200ms 轨迹周期，而用例直到周期结束后才开始续租。临时恢复旧扫描的 1 秒/5ms 时序仍复现同一租约过期，说明该对照不支持把失败归因于新扫描时序。已为这项“健康操作员下的记录隔离”测试补齐等待期间续租，租约失效本身仍由其他用例覆盖；产品租约/失能逻辑没有改动。

产物目录 `hmi/dist/cold-start-discovery-20261030/` 保存最终测试日志、旧时序对照日志、源码清单、验证报告和 SHA256。均为假设备与合成数据，不是现场采集记录。

本轮没有访问真实 PLC/CAN，没有执行运动、故障复位或固件升级；测试“长期运行保护”用例不等于已经做过数小时实机稳定性测试。
