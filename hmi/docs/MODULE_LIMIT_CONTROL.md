# 真机整模块限位检查

候选版本 `3.0.34~limitcheck3`。打开「限位块检查 → 真机检查」，系统取本窗口已应用的真实模块和样机编号。工位方案已核定、CAN 已连接且电机已扫描和使能时，点击「检查限位装置」。配置启用内置轨迹的工位在预检通过后直接启动。工位先读取当前姿态、核对回位路径并自动回到轨迹起点，随后逐项检查，完成后回到工装方案的起点，发送失能指令并保存实测结果。

## 检查范围和执行顺序

- 左右 5 自由度腿各 10 个方向。内置路径在同一次屈膝中完成两个髋侧摆方向，髋回中后再展开。踝俯仰和侧摆通过现有闭链角度及力矩映射判定。
- 左右 5／7 自由度臂各 10／14 个方向。内置路径先屈肘，肩部六个方向测完并回中后，再检查肘和腕。
- 腰髋检查腰侧摆和腰旋转的上下限，共 4 个方向。标准腰髋站的两台髋电机保持进入试验时的角度并接受反馈监视。它们的目标角在整轮内恒定，试验窗口只包含两台腰电机对应的逻辑轴。

程序按工装批准顺序转场、核对到位、缓慢推进，通过新鲜逐电机反馈判断角度停滞和力矩上升。候选产生后停止推进、卸载跟踪偏差并沿实测路径缓退。候选在容差内且完成缓退时，先退出到上一个搜索起点，再沿核定路径进入下一方向。异常止挡、未检出、超力矩、反馈失效、退路不满足、租约撤销或中止操作都会停止当前任务并请求失能。设备实际失能回读与指令发出状态分别展示。

## 工位方案

管理员维护 `/etc/rp1-factory-hmi/limit-probe.d/<模块>.sequence.json`，文件与目录须由管理员所有，普通用户只读。示例放在候选包交付目录 `profiles/`，其中工装角度、增益与门限特意留空。量产参考范围、现有运动坐标与具体工装的可达路径需要按实际装配核定。

| 字段 | 填写要求 |
| --- | --- |
| `fixture`, `revision`, `approved_by`, `station_sha256` | 实际工装身份和修订，填核定人及界面显示的工位配置 SHA256。 |
| `home_deg` | 整条轨迹的起点及正常结束后失能的安全支撑姿态。上位机从当前姿态自动回到该点。腰髋中后两列是核定髋保持角的参考。 |
| `entry_via_deg` | 可选。填写从当前姿态回到 `home_deg` 前需经过的回位点。省略时预检并使用直接回位路径。回位通道须符合工装可达范围。 |
| `use_builtin_trajectory` | 启用后由当前模块的内置资源提供检查顺序、固定轴姿态和检查项之间的过渡点。工位方案提供被检查轴的接近角、搜索起始角、增益、行程和保护参数。每项的 `via_deg` 留空以采用内置过渡点。 |
| `waist_hip_hold_bounds_deg` | 腰髋可选。两个髋轴分别填写 `[最小角, 最大角]`，范围须包含 `home_deg` 的对应髋角。省略时使用核定保持角 ±0.12°。两条髋轴从进入试验起始终保持实测角。 |
| `windows` | 每个受检方向恰好一次，数组顺序为执行顺序。每个 `via_deg` 是从上一方向的 `search_pose_deg` 到本项 `staging_pose_deg` 的路径点，第一个方向从 `home_deg` 出发。空 `via_deg` 表示直线转场。 |
| `point` | 独立填写复位和搜索角、行程、速度、`Kp/Kd` 倍率、中止力矩、候选判定、跟踪与缓退参数，沿用单方向试点的字段和核定规则。|
| `joint_peak_nm` | 可选。按具名逻辑关节顺序填写已核实的峰值力矩，各项的 `joint_abort_nm` 不得超过对应峰值。电机侧的中止值单独核定。 |
| `transfer_speed_deg_s` | 可选。整轮回位、检查项之间转场和回起点使用的最高指令速度，可设至 10°/s。空值沿用各项中最低的定位速度。 |
| `return_via_deg` | 最后一次搜索起点至 `home_deg` 的核定路径点。|

全部向量按当前工位具名关节顺序填写。腰髋的实际工位向量仍为四列，后两个髋轴的角度在所有航点相同，并需保留对应的中止力矩。转场力矩及跟踪保护采用各点所核定的最低门限。离开搜索区域使用转场速度和该项定位速度中的较小值。实际样机、配置修订、工装路径和门限一并进入启动摘要。模拟 NPZ 对应的是离线预演。

搜索按有效逐电机反馈的实际间隔推进，达到核定行程时停止向前推进。速度或单帧限幅要求更小的推进量时，自动延长运动段。备检位到搜索位的复位时程按需要移动的距离计算。搜索起点到量产参考角的距离须容许方案指定的缓退。

## 实现与本地记录

`factory_hmi/core/module_limit_check.py` 的 `ModuleCycle` 顺序调用 `ProbeCycle`；`ModuleWorker` 复用工位的 MIT 下发、逐电机反馈、急停和失能流程。`core/service.py` 在交接控制前验证核定的起点和全部转场及试探段。`gateway/station_process.py` 核对控制租约、CAN 归属并阻止并行运动。`desktop/module_limit_panel.py` 从当前样机发起一次任务，呈现已完成的方向及当前阶段。

实测完成或中止后保存 `${RP1_FACTORY_DATA_ROOT}/limit-checks/<检查标识>.json`，也可从界面导出。报告包括每方向实测角、参考值、力矩基线与阻挡窗口、缓退距离、对应的逐电机反馈、停止原因和失能状态。`calibration_passed` 留空供工装验收，数据保存在本地。

安装包的 `resources/limit-replay/manifest.json` 为当前模块登记转场文件及 SHA256。开始检查前，上位机把内置过渡点、固定轴姿态与现场搜索参数合成一份方案，再执行既有工位预检。模型止挡角存于回放数据，工位仍按量产参考角评估实测止挡。模型台架间隙与实机保护参数需现场核定。
