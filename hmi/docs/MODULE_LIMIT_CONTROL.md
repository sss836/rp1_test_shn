# 姿态验证：左臂从零搜索限位

版本：3.0.34~limitcheck7。本文描述源码和交付包行为；现场安装及验证结果另见本批次 BUILD_REPORT.md。

## 本次解决的问题

之前页面同时放置真机检查、连续轨迹、真机试点和模拟验收，入口容易混淆。真机整模块入口还必须读取 `/etc/rp1-factory-hmi/limit-probe.d/left_arm.sequence.json` 或 `left_short_arm.sequence.json`；没有文件时在预检返回 409。原来的单方向执行器主要设计为从参考限位附近开始搜索，不能把这个行为当作从零完成整臂检查。

现在侧栏只保留「姿态验证」，不再实例化那三个演示/试点分页。结果通过真实控制服务产生。左臂 5 轴、7 轴缺少外置方案时自动生成可执行的内置方案，依据本机当前具名关节、CAN、ID、方向和 Kp/Kd 绑定配置摘要，不要求手工复制模板或填写审批人。存在有效外置方案时仍尊重它；损坏、不可读或映射不符的文件不会被静默覆盖。右臂、腿和腰部的已有执行器及外置方案逻辑不变，本次没有将左臂参数套到其他模块。

## 操作和执行顺序

1. 在「样机配置与连接」应用左臂 5／7 轴模块，填写样机编号，连接 CAN、扫描并使能。使能仍是独立操作。
2. 点击「开始姿态验证」。桌面窗口使用现有本地操作权限，预检后直接提交一次任务；不要求平台登录，也不额外弹出逐项确认。
3. 网关核对当前配置摘要、控制租约、逐电机反馈和当前任务状态。控制器先将第一帧目标设为当前实测姿态，再平滑移动到所有逻辑关节 0°。不写编码器零偏，不要求人员先摆正。
4. 回零实测到位后，根据既有顺序资源提取“具名关节、上/下限方向”。忽略该资源中的仿真止挡角、时间轴、固定姿态和转场航点，不加载 NPZ 播放器。
5. 每个方向从逻辑零点开始推进受检轴，其余轴仍下发零位目标；以进入该方向时的实测保持位监测偏移（最多 3°），所有轴仍受 5°指令跟踪限制，持续核对新鲜逐电机反馈。左臂 5 轴共 10 项、7 轴共 14 项。
6. 同时满足角度停滞、目标继续推进、力矩上升后，立即记录候选实测角和判定窗口；停止向前推进，撤掉跟踪偏差，再沿已走过的实测路径退让约 1°。退让完成后返回零位，自动进入下一方向。
7. 全部正常完成后回零、请求电机失能并保存报告。提前受阻、未检出、反馈失效、过载或操作员中止时，停止后续搜索并请求失能；报告仍保留已测项、候选点和中止原因，不强行执行回零。

## 默认判定与速度

| 项目 | 当前内置值/规则 |
| --- | --- |
| 初次回零及普通转场 | 平滑时程，最高目标速度 20°/s；还受现有工位单帧/速度约束 |
| 内置左臂准备到位 | 所有轴距目标不超过 3°（受更小跟踪门限约束），连续 0.2 秒停稳；允许 0.05°反馈极差噪声。目标仍为零，不写零偏，不把该容差当限位测量精度 |
| 搜索推进 | 最高 5°/s；距参考角 6°以内或跟随滞后超过 0.35°时降至最高 1°/s |
| 接触窗口 | 连续 1 秒；至少 3 个新鲜样本；角度极差不超过 0.2°；目标仍沿检查方向推进 |
| 力矩条件 | 窗口内绝对力矩持续不低于 `max(0.5 N·m, 实测基线 + 0.5 N·m)` |
| 基线 | 搜索前取得；长行程中只在实际沿搜索方向运动且跟随误差小于 0.3°时，用最近最多 25 个运动样本的力矩中位数更新。发生停滞/跟随滞后后冻结，避免把阻挡力矩吸收为正常负载 |
| 参考偏差 | 实测角与量产参考角比较，默认 ±3°；参考角不是动作的成功终点 |
| 指令行程 | 从零向参考方向，最多到参考角外 2.9°；没有同时满足接触判据就记录未检出，不将目标角当实测值 |
| 跟随误差 | 内置整臂方案 5°；原单方向试点的 2°上限不变 |
| 反馈/失能 | 继续使用原有逐电机身份、时间新鲜度、驱动故障、过温及失能回读规则 |

这些是软件默认检查参数，模拟通过不等于台架碰撞间隙、真实负载和接触判别已经通过现场验收。零点和角度正方向必须对应当前实际装配；本次未执行真实电机动作。

中止力矩不使用接触检测的小门限作为中止门限。默认取“已有工位高力矩阈值”与“各型号产线脚本力矩编码范围上限”的较小值。可以在当前模块 YAML 的 `factory_hmi.limit_check.joint_peak_nm` 中按完整具名关节提供实际峰值上限，再逐轴取较小值。产线编码范围并不代表机械关节额定峰值，未填写实际峰值时报告明确记录 `station_cap_and_production_range`，不伪造峰值核定。

本机现有配置的默认中止值：左臂 5 轴各 35 N·m；7 轴的肩、肘、腕侧摆各 35 N·m，腕旋转和腕俯仰各 30 N·m。实际应用的较低工位限制继续生效。

## 页面及文件连接

- `core/arm_limit_defaults.py`：`builtin_arm_profile` 生成当前两种左臂的完整默认方案，采用既有电机增益和型号参数，不联网、不改写设备参数。
- `core/module_limit_check.py`：`load_module_plan` 处理缺失文件；`apply_builtin_trajectory` 的 order-only 分支只取顺序；`ModuleCycle` 组织实测回零、逐向搜索、退让和收尾；`ModuleWorker` 保存候选及整轮报告。
- `core/live_limit_probe.py`：`ProbeCycle` 负责有界推进、运动力矩基线、停滞+力矩判定和按实测轨迹退让。旧腿部试点限制保持兼容。
- `core/service.py`：预检生成摘要，启动再次核对摘要和最新姿态，一次摘要只能发起一次任务；故障或中止进入现有失能通道。
- `desktop/pose_validation_view.py`：模块状态卡、四阶段进度、当前实测及结果表。未测项显示“—”；引用的是实际状态，没有演示结果填充。当前实际角是实时值，表内实测角是已记录的候选止挡角。
- `desktop/module_limit_panel.py`：点击、预检、启动、每 500 ms 状态刷新、中止及导出。只有一个挂起刷新；隐藏页面停止定时器，后台任务由现有控制租约管理。
- `desktop/app.py`：单个姿态验证入口，删除三个分页的实例化及退出清理引用，保留其他测试页面。

实时状态只返回当前状态和少量逐项结果；完整采样证据仅在结束保存或显式导出时读取。候选一旦产生即保留，即使退让失败也不会丢失；这种记录标记退让未完成，不能当作已完成项目。

## 本地记录与权限边界

报告自动写入现有数据根目录下 `limit-checks/<检查标识>.json`，采用临时文件、fsync 和原子替换。包括：模块/样机/配置摘要、实际起始姿态、零位目标、逐项实测角/参考角/偏差、力矩基线/阻挡窗口、退让距离、轨迹证据、中止原因及失能结果。逐方向轨迹保留最多 5000 个样本并标明是否截断；对应原始 Iq、Kt、估算来源和力矩一并记录。

109 继续使用现有 Iq×该电机实测 Kt 换算，页面标记估算；108 继续使用原驱动反馈力矩。本次不改协议控制、固件刷写、参数更新、老化测试或工厂快速验证路径。

数据保存在本机，本功能不会自动提交平台，不进入正式测试统计；`calibration_passed` 仍为空，逐项只表达与参考角的比较结论。外部覆盖方案仍须保留来源和原有完整性校验。内置方案不伪装为已获工装验收。

## 验证范围

隔离测试覆盖非零起点回零、5/7 轴整轮、偏移的模拟止挡角、提前受阻、未检出、过载和反馈断续；桌面测试验证一次点击先预检再启动、移除三个分页、未就绪解释和估算力矩标注。还验证原腿部闭链/腰髋、旧试点、客户端权限、软件退出等相关回归。实际统计与包内验证结果保存于本批次交付报告；尚未执行真实硬件接触限位测试。

## limitcheck7：回零后中止修复（2026-11-17）

现场 limitcheck6 报告在开始搜索前记录「转场命令已发完，未确认到位」，结果数为 0；最后实测肩俯仰 +2.8086°、肘部 -2.8305°。代码原先用所有轴 ±0.12°作为转场到位条件，目标时程结束 3 秒未满足就抛出 FeedbackError；ProbeWorker finally 请求失能。首次起点含约 164.46°旋转，原 10°/s 五次平滑时程理论约 30.84 秒。报告没有保存回零逐帧证据，不能据此确定偏差源于重力、增益还是其他机械原因。命令跟踪叠加相同末态偏差的隔离模型复现了同一中止，不等同于回放真实控制记录。

修复范围仅为内置左臂 5／7 轴的准备/衔接：回零上限 20°/s，现有单帧及工位速度约束照常参与；准备到位容差、进入 ProbeCycle 的起点容差、基线稳定判断和非搜索轴保持判断一致使用上述规则。旧试点与外置非 full_range_search 方案仍用原规则、10°/s转场上限。没有增大 Kp/Kd、接触力矩、中止力矩或驱动控制范围。回零超过范围或持续未停稳仍中止，并给出具体关节、实测角、目标角、偏差和容差。

到位容差不是止挡检测门限：停滞角极差 0.2°、1 秒窗口、力矩上升、实测退让至少约 1°及逐电机新鲜度均不变；不会因进入 ±3° 就登记一个限位成功结果。软件未确认退让距离时不能继续下一项。

界面在操作按钮下方直接显示中止原因，回零卡片显示最大偏差与容差，回零百分比是目标时程进度。ModuleCycle 现在保留最后一帧转场信息（包括异常帧）及最多 5000 条、最高约 10 Hz 的转场证据；完整报告另保存最后逐电机反馈。UI 的 500 ms 查询仅返回最后一帧，不反复传输整段轨迹。该记录不提交平台、不更改既有正式数据流程。
