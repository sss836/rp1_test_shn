# 姿态验证：所有整模块统一反馈搜索

版本：3.0.34~limitcheck8。本文描述源码和交付包行为；构建不代表安装或真实设备验证。

## 本次解决的问题

之前页面同时放置真机检查、连续轨迹、真机试点和模拟验收，入口容易混淆。真机整模块入口还必须读取 `/etc/rp1-factory-hmi/limit-probe.d/left_arm.sequence.json` 或 `left_short_arm.sequence.json`；没有文件时在预检返回 409。原来的单方向执行器主要设计为从参考限位附近开始搜索，不能把这个行为当作从零完成整臂检查。

侧栏只保留「姿态验证」，结果通过真实控制服务产生。左右 5/7 轴手臂、左右 5 轴腿及腰部两轴的整模块检查共用反馈搜索执行器。缺少外置方案时，按当前具名关节、CAN、ID、方向、Kp/Kd、参考角及各模块已有避让资源生成内置方案，绑定配置摘要。存在有效外置方案时使用它的几何、增益、力矩和行程；损坏、不可读或映射不符的文件不会被静默替换。整模块执行速度统一为下表策略，并在报告中记录实际生效的方案摘要。

## 操作和执行顺序

1. 在「样机配置与连接」应用对应模块，填写样机编号，连接 CAN、扫描并使能。使能仍是独立操作。
2. 点击「开始姿态验证」。桌面窗口使用现有本地操作权限，预检后直接提交一次任务；不要求平台登录，也不额外弹出逐项确认。
3. 网关核对当前配置摘要、控制租约、逐电机反馈和当前任务状态。控制器先将第一帧目标设为当前实测姿态，再平滑移动到模块起点；手臂默认逻辑零，腿/腰保留各自配置和避让要求。不写编码器零偏，不要求人员先摆正。
4. 零位目标发送完并确认实测停稳后，根据既有顺序资源提取“具名关节、上/下限方向”。忽略该资源中的仿真止挡角和时间轴，不加载 NPZ 播放器。MIT 负载角差只记录，不以固定目标角差拒绝衔接。
5. 每个方向从该项搜索起点推进受检轴。默认左/右肩 yaw 两方向分别采用已有下垂肘目标约 −80.803°／+80.803°；腿按既有路线在髋侧摆期间屈膝；腰只生成 roll/yaw 的四个方向，髋轴保持。整模块不以固定目标角差判停。5 轴共 10 项、7 轴共 14 项，腿每条 10 项，腰共 4 项。
6. 实际运动时更新负载基线；停止跟随时冻结基线，同时检查角度停滞和力矩增量。到搜索预算末端停止推进，最多补完 1.2 秒的判定窗口，不能仅因指令停止就丢掉接触判定。候选来自实测窗口的角度中位数。随后受检轴沿反方向撤掉指令压力，按实际净位移退让约 1°；起点附近提前受阻则退到实际搜索起点，不强求不存在的 1°退路。
7. 退让确认后返回零位，继续下一方向。提前阻挡、超出参考、未检出均保留异常结果，不直接中止整轮。退让失败、反馈失效、过载、驱动故障或操作员中止仍停止并请求失能，不强行回零。全部方向完成后回零、失能并保存报告，完成不等于所有限位合格。

## 默认判定与速度

| 项目 | 当前内置值/规则 |
| --- | --- |
| 初次回零及普通转场 | 平滑时程，最高目标速度 20°/s；还受现有工位单帧/速度约束 |
| 整模块准备衔接 | 起点/转场目标发送完后，连续 0.2 秒观察实际停稳，噪声极差容许 0.2°。目标角差只记录，不设另一套固定角差中止或到位门限；未停稳时保持目标并显示等待，仍逐帧检查力矩和反馈。不写零偏，不能把发送零目标当作实测严格到零 |
| 搜索推进 | 最高目标速度 10°/s；距参考角 6°以内，或失去跟随且力矩增大时降至最高 2°/s；回程、转场、退让目标速度20°/s。实际推进仍受每帧/映射约束 |
| 接触窗口 | 连续 1 秒；至少 3 个新鲜样本；角度极差不超过 0.2°；有相对运动负载偏差的额外推进压力，恒定目标也可判定 |
| 力矩条件 | 至少 80% 窗口样本的绝对力矩达到 `max(0.5 N·m, 实测基线 + 0.5 N·m)`；单个低毛刺不清空候选，单个高毛刺不能生成候选；瞬时中止力矩仍优先执行 |
| 基线 | 搜索前用 0.2 秒停稳样本取得；运动中用最近 0.5 秒有效运动负载的中位数更新。近 0.2 秒实测沿搜索方向移动超过 0.1°、且至少跟随目标增量的一半，才更新；不限制绝对跟踪误差必须小于 0.3°。失去跟随时冻结 |
| 参考偏差 | 实测角与量产参考角比较，默认 ±3°；参考角不是动作的成功终点 |
| 搜索预算 | 实际搜索范围仍为零位至参考角外 2.9°；指令上限补偿运动时实测的负载角差，不再用 4.8°领先量封顶，也不截断负载角差为 ±5°。行程预算耗尽便停止推进，补完判定；实际越界超过一个配置电机步长仍中止。不伪造限位 |
| 跟随误差 | 所有整模块的回零、基线、搜索、退让、转场及保持轴均不以固定目标角差判停；角差仍如实记录。独立单方向试点不属于此整模块归一化入口。预检到首帧之间的实际姿态变化核对仍在 |
| 反馈/失能 | 取消35ms组内时间差判停/等待，时间差仅记录；逐电机150ms有效期、完整新组等待预算、身份、驱动故障、过温及失能回读继续检查，重复帧不推进 |

这些是软件默认检查参数，模拟通过不等于台架碰撞间隙、真实负载和接触判别已经通过现场验收。零点和角度正方向必须对应当前实际装配；本次未执行真实电机动作。

中止力矩不使用接触检测的小门限作为中止门限。默认取“已有工位高力矩阈值”与“各型号产线脚本力矩编码范围上限”的较小值。可以在当前模块 YAML 的 `factory_hmi.limit_check.joint_peak_nm` 中按完整具名关节提供实际峰值上限，再逐轴取较小值。产线编码范围并不代表机械关节额定峰值，未填写实际峰值时报告明确记录 `station_cap_and_production_range`，不伪造峰值核定。

本机现有配置的默认中止值：左臂 5 轴各 35 N·m；7 轴的肩、肘、腕侧摆各 35 N·m，腕旋转和腕俯仰各 30 N·m。实际应用的较低工位限制继续生效。

## 页面及文件连接

- `core/arm_limit_defaults.py`：`builtin_arm_profile` 生成当前两种左臂的完整默认方案，采用既有电机增益和型号参数，不联网、不改写设备参数。
- `core/module_limit_check.py`：`load_module_plan` 处理缺失文件；`apply_builtin_trajectory` 的 order-only 分支只取顺序；`ModuleCycle` 组织实测回零、逐向搜索、退让和收尾；`ModuleWorker` 保存候选及整轮报告。
- `core/live_limit_probe.py`：`ProbeCycle` 对 `full_range_search` 调用新反馈搜索器，`PositionMove` 统一准备与跟踪容差。旧近限位试点继续走原分支。
- `core/feedback_limit_search.py`：`LoadContact` 更新和冻结基线、统计停滞窗口；`FeedbackLimitSearch` 控制有界推进、末端判定及按实测净位移退让，逐帧优先执行力矩中止。
- `core/service.py`：预检生成摘要，启动再次核对摘要和最新姿态，一次摘要只能发起一次任务；故障或中止进入现有失能通道。
- `desktop/pose_validation_view.py`：模块状态卡、四阶段进度、当前实测及结果表。未测项显示“—”；引用的是实际状态，没有演示结果填充。当前实际角是实时值，表内实测角是已记录的候选止挡角。
- `desktop/module_limit_panel.py`：点击、预检、启动、每 500 ms 状态刷新、中止及导出。只有一个挂起刷新；隐藏页面停止定时器，后台任务由现有控制租约管理。
- `desktop/app.py`：单个姿态验证入口，删除三个分页的实例化及退出清理引用，保留其他测试页面。

实时状态只返回当前状态和少量逐项结果；完整采样证据仅在结束保存或显式导出时读取。候选一旦产生即保留，即使退让失败也不会丢失；这种记录标记退让未完成，不能当作已完成项目。

## 本地记录与权限边界

报告自动写入现有数据根目录下 `limit-checks/<检查标识>.json`，采用临时文件、fsync 和原子替换。包括：模块/样机/配置摘要、实际起始姿态、零位目标、逐项实测角/参考角/偏差、力矩基线/阻挡窗口、退让距离、轨迹证据、中止原因及失能结果。逐方向轨迹保留最多 5000 个样本并标明是否截断；对应原始 Iq、Kt、估算来源和力矩一并记录。

109 继续使用现有 Iq×该电机实测 Kt 换算，页面标记估算；108 继续使用原驱动反馈力矩。本次不改协议控制、固件刷写、参数更新、老化测试或工厂快速验证路径。

数据保存在本机，本功能不会自动提交平台，不进入正式测试统计；`calibration_passed` 仍为空，逐项只表达与参考角的比较结论。外部覆盖方案仍须保留来源和原有完整性校验。内置方案不伪装为已获工装验收。

## 验证范围

隔离测试覆盖非零起点回零、5/7 轴整轮、偏移的模拟止挡角、提前受阻、未检出、过载和反馈断续；桌面测试验证一次点击先预检再启动、移除三个分页、未就绪解释和估算力矩标注。还验证原腿部闭链/腰髋、旧试点、客户端权限、软件退出等相关回归。实际统计与包内验证结果保存于本批次交付报告；尚未执行真实硬件接触限位测试。

## 历史：limitcheck7 的回零后中止修复（已由上述 v3 逻辑替代）

现场 limitcheck6 报告在开始搜索前记录「转场命令已发完，未确认到位」，结果数为 0；最后实测肩俯仰 +2.8086°、肘部 -2.8305°。代码原先用所有轴 ±0.12°作为转场到位条件，目标时程结束 3 秒未满足就抛出 FeedbackError；ProbeWorker finally 请求失能。首次起点含约 164.46°旋转，原 10°/s 五次平滑时程理论约 30.84 秒。报告没有保存回零逐帧证据，不能据此确定偏差源于重力、增益还是其他机械原因。命令跟踪叠加相同末态偏差的隔离模型复现了同一中止，不等同于回放真实控制记录。

修复范围仅为内置左臂 5／7 轴的准备/衔接：回零上限 20°/s，现有单帧及工位速度约束照常参与；准备到位容差、进入 ProbeCycle 的起点容差、基线稳定判断和非搜索轴保持判断一致使用上述规则。旧试点与外置非 full_range_search 方案仍用原规则、10°/s转场上限。没有增大 Kp/Kd、接触力矩、中止力矩或驱动控制范围。回零超过范围或持续未停稳仍中止，并给出具体关节、实测角、目标角、偏差和容差。

到位容差不是止挡检测门限：停滞角极差 0.2°、1 秒窗口、力矩上升、实测退让至少约 1°及逐电机新鲜度均不变；不会因进入 ±3° 就登记一个限位成功结果。软件未确认退让距离时不能继续下一项。

界面在操作按钮下方直接显示中止原因，回零卡片显示最大偏差与容差，回零百分比是目标时程进度。ModuleCycle 现在保留最后一帧转场信息（包括异常帧）及最多 5000 条、最高约 10 Hz 的转场证据；完整报告另保存最后逐电机反馈。UI 的 500 ms 查询仅返回最后一帧，不反复传输整段轨迹。该记录不提交平台、不更改既有正式数据流程。

## 左臂 7 轴腕部边界复搜

`core/feedback_limit_search.py` 对左 7 轴腕旋转下限和腕俯仰上限增加一次复搜。首轮到达指令或实测行程边界并完成接触窗口后，若证据不足，先按方案退让，等待实测位移、卸载及停稳，再从退让位置重采基线，以最高 1°/s 重新接近。两轮共用从原搜索起点计算的行程预算、指令增量限制和力矩中止。接触仍由实测角度停滞、持续力矩上升及相对运动基线的指令推进共同判定。第二轮证据仍不足时，结果为「未检出」，止挡角留空。

`core/module_limit_check.py` 保存各轮结束原因、指令角、实测角、末端力矩、门槛及已确认的退让距离。`desktop/pose_validation_view.py` 展示首轮和复搜状态，可悬停查看结束证据。11 月 18 日三轮历史样本的腕旋转下限和腕俯仰上限都通过了角度停滞条件，但各自没有达到运行中的力矩门槛。旧样本离线回放用于核对接触判定，复搜路径使用合成反馈验证。

### 同一轮延伸搜索

左右 5/7 轴臂、左右 5 轴腿和腰部两轴的整模块计划在启动预检时按方向生成延伸范围。默认实测边界为量产参考角向搜索方向外移 10°。例如左 7 轴腕旋转下限从 −85° 得到 −95°，腕俯仰上限从 +70° 得到 +80°。已有核定工位方案的显式实测和目标边界继续作为该工位的边界使用。

程序在原普通行程用罄时保持本轮基线和反馈窗口，沿同一方向以最高 1°/s 继续增加目标。默认目标随实测位移调整，纳入实际运动时的跟踪偏差和接触窗口内可推进量。关节持续停滞时收完一轮接触证据，完成退让并记录结果。预检扫描到实际边界，逐帧仍检查关节和电机目标范围。搜索及退让阶段越过实测边界会中止，角度停滞、持续增载的接触判定和力矩中止继续执行。

使用完行程仍缺接触证据时显示「行程到界 · 止挡待确认」。保持目标等待后仍缺增载证据时显示「推进停滞 · 止挡待确认」。报告保留搜索终点、目标和力矩，止挡角留空。量产参考角用于比较，软件不写入电机零位。
