# PLC 上位机双工位改造实现与验证

基于 PLC 上位机 v3.0.25（`091e867`）的独立开发树，分支为 `codex/plc-hmi-dual-station-20261110`。本文记录启动拓扑、工位与柜控边界，以及已执行的软件验证。

```text
Qt 窗口 A ─┐                     ┌─ 工位 A 控制进程 ── 独占 CAN / 本地 CSV
            ├─ 本机网关 ─────────┤
Qt 窗口 B ─┘                     ├─ 工位 B 控制进程 ── 独占 CAN / 本地 CSV
                                  └─ 共享 PLC 柜进程 ── PLC 协议与回执
各工位已关闭的 CSV ── 持久报告任务 ── 独立报告进程 ── 封存证据及本地历史索引
```

## 启动、控制和隔离

- [launch.py](../launch.py) 的 `DesktopChildren` 通过继承的私有通知管道受理“新开窗口”，最多同时持有两个 Qt 子进程。两个窗口使用同一网关地址、各自的客户端身份和租约。重复点击桌面启动图标执行窗口唤起。第一个窗口安全退出后，第二个继续运行。最后一个窗口退出后，启动器才执行全局关停握手。
- [gateway/app.py](../factory_hmi/gateway/app.py) 保留平台会话、REST、WebSocket、工位路由和归档入口。[gateway/station_process.py](../factory_hmi/gateway/station_process.py) 为每个工位启动独立的 Python 子进程，执行 `FactoryService`、电机控制循环、CAN 访问、记录和本地保护。控制、保护、续租、只读状态和记录命令各用独立私有通道。通道有长度和等待上限，超时后的控制结果按未确认处理，需先安全恢复。迟到的同一条关闭成功回执可核对，重复请求不重放关闭。
- 工位按解析后实际使用的 CAN 接口加锁。真实接口的锁按本机接口名排他，模拟接口的锁按隔离数据根目录排他。电机断开、CSV 收尾和 CAN 下线回读确认后才释放。固件和参数维护由网关协调，先从工位取得传输占用。进程或驱动彻底失去响应时，软件显示状态未确认，现场需依据独立的实际反馈判断设备状态。
- [gateway/lease.py](../factory_hmi/gateway/lease.py) 和工位安全线程按控制代次撤销过期租约。PLC 供电的快速验证由工位独立读取相应通道许可和实际供电反馈。许可丢失触发本工位的取消和保护清理。网关私有租约通道中断时，工位也独立撤销权限，机构仍需承重时保留保护阻尼和支撑确认流程。维护传输结果未确认时保留 CAN 占用。
- [plc/process.py](../factory_hmi/plc/process.py) 单独持有唯一柜服务。[plc/coordination.py](../factory_hmi/plc/coordination.py) 的指令回执、超时和状态推进在柜轮询及柜指令线程中执行。窗口只读取快照。单工位退出不会直接改变共用柜的供电，正常全局退出再核对柜停机回执。总停止导致主电源丢失时，协议会撤销 PS1 实际状态确认，柜服务保留关停待确认状态。该情况在 v3.0.25 与本次代码上均可复现。
- [desktop/app.py](../factory_hmi/desktop/app.py) 的 `closeEvent` 异步发起带控制代次的工位关闭。已确认释放才退出。超时或拒绝时窗口保留，操作员可核对后重试。

## 工位状态与预览

- [gateway/display.py](../factory_hmi/gateway/display.py) 的 `DisplayPublisher` 为一个运行会话生产一份最新状态。缓存保留不可变 JSON 文本、单调采样时刻、UTC 时刻和递增序号。默认 10 Hz，最高 30 Hz，单帧上限 1 MiB。读取只取得缓存引用，慢客户端不积压历史状态。关闭立即失效缓存，后台采样尚未退出时返回可核对的关闭结果。
- [core/service.py](../factory_hmi/core/service.py) 的 `collect_display_snapshot` 由后台生产者调用，空闲反馈沿用驱动允许的只读采样规则。实际 Netlink 状态最多每秒采一次，在服务锁外执行请求，回锁时核对配置版本和采样顺序。展示缓存超过 2.5 秒按过期处理。[`FactoryController.sample_display_feedback`](../factory_hmi/core/controller.py) 使用非阻塞控制器锁。纯展示的 `display_snapshot` 消费带时间戳的缓存，原设备命令仍可用原来的实时检查。
- [gateway/preview.py](../factory_hmi/gateway/preview.py) 和 [core/telemetry_hub.py](../factory_hmi/core/telemetry_hub.py) 给本地实时预览设置独立预算。默认批次取最多 64 个最新帧，帧数据预算 256 KiB。游标未连续时返回 `sequence_gap`，已收到的新帧以源时间戳为准。WebSocket 的工位 IPC 在事件循环外处理，慢写入超过 1 秒结束该连接。实时缓存的丢帧只影响展示，工位 CSV 仍由记录线程保存。
- [gateway/local_curves.py](../factory_hmi/gateway/local_curves.py) 通过 `preview_record_identity(run_id)` 读取当前执行身份，仍从工位自有记录目录查找已持久化窗口。票据绑定执行，读取过程中换了执行也拒绝发送。已封存曲线继续按索引读取封存证据。

## 停机边界和正常执行报告

- [core/service.py](../factory_hmi/core/service.py) 的 `close(disconnect_can=True)` 用于隔离工位。电机安全断开并确认 CSV 写入收尾后，复用 `can_disconnect` 的回读逻辑，要求所有已配置接口都有返回且均处于关闭状态。缺接口或任一仍为 UP 时保留关闭失败状态和原有隔离，等待明确的安全确认。真实关闭确认后才归档 Pn 隔离记录。清除配置也复用同一检查，回读不完整时保留配置身份。
- 工位控制进程解析 YAML 后，用该对象确定 CAN 接口并传给 `FactoryService.configure`。工位配置保持使用同一份解析结果，两个步骤之间更换同名文件不会改变已认领的接口。
- `_finalize_after_run` 使用原执行的播放对象冻结终止上下文。CSV 写入未结束或已有写入错误时，不入报告队列。确认后，调用 [core/report_jobs.py](../factory_hmi/core/report_jobs.py) 的 `enqueue_report_job`，把源路径、执行身份和上下文写进现有的 `report-jobs.sqlite3`。SQLite 写事务限制同一报告根目录最多 8 个活动任务，同 ID、同源路径和同上下文去重，冲突载荷拒绝。
- 每个报告根目录通过进程锁同时只运行一个报告计算进程。计算进程继承必要的便携运行库路径，使用独立地址空间、单线程数值库和资源预算（1 GiB 地址空间、900 秒计算预算），读取已关闭的本地 CSV，沿用 `ReportManager` 的封存规则。其余工位可以继续工作。主动等待报告结果仍使用 `wait_for_reports`，工位正常关闭只等待本地写入与持久接单。网关在工位退出后接管调度，网关重启时重新领取已接单任务。已封存报告通过原有校验后恢复回执。
- 待处理任务可直接取消，运行中的任务在封存发布边界确认取消。封存已进入提交阶段时，状态保留至索引和回执收尾。源 CSV 始终保留，原有核实、上传、审批和统计流程仍走各自入口。手动追加分析和旧历史文件恢复继续使用既有流程。

## 已完成的软件验证

- Ubuntu 22.04 断网容器中，真实启动器启动了两个 Qt 窗口、两个模拟工位进程、一个网关和一个 mock PLC 柜。关闭第一窗后第二窗的进程和租约继续有效，最后一窗退出后启动器返回 `running=false`。
- Ubuntu 22.04 聚焦回归 89 项通过，Ubuntu 24.04 的工位、柜控和报告聚焦回归 20 项通过。覆盖模拟左臂和右腿同时运行与记录、同 CAN 拒绝、错误控制代次拒绝、暂停 A 后 B 的快照和续租继续、PLC 单通道许可撤销、关闭回执超时重试、网关通道失联时保留保护阻尼，以及已确认释放后另一工位继续运行。
- PLC 子系统另有 246 项聚焦回归通过。实际本机 TCP 启动模拟柜，验证了双窗口共享回执、过期版本拒绝和正常全局退出。
- 在本地隔离 Python 环境执行 42 项聚焦回归，均通过。覆盖报表真实子进程、重复入队、待处理取消、工位关闭与文件交接、新工位重启恢复、展示缓存以及预览打包、CAN 下线回读和配置单次解析。
- 在无外网的 Ubuntu 22.04 容器中，以旧 Jammy 包实际自带的 Python 和运行库挂载新源码执行 20 项聚焦回归，均通过。覆盖报表进程在便携解释器下真实生成报告和读取索引。这里验证的是运行库兼容，待最终安装包另行验证。
- 扩展运行中的 6 项快速验证失败在 v3.0.25 的同一 Jammy 环境亦可复现。另有旧版即可复现的生命周期夹具、历史 CSV 换行和故障收尾断言。记录按项区分旧基线与新增用例，聚焦通过不代表全量通过。
- 软件验证使用 mock PLC、fake CAN 和合成轨迹。现场验收需测双工位控制周期和采样缺口、共享 CAN 转接器负载、连续运行，以及真实 PLC 停止和电机失能反馈。当前为本地源码改动，尚未打包或替换现场实例。
