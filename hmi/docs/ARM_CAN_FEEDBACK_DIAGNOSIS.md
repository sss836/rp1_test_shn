# 七轴手臂 ID 7 的上位机判定

修复基于工厂上位机 v3.0.39，原版提交为 `2e48abc`。核对过发布包的 SHA256，包内的上位机后端、控制器、桌面主窗口源码和原生 SDK 构建清单与标签一致。现场发生报警时的收发记录仍是确认原因所需的证据。

## 判定与界面

| 本次可核实的事实 | 判定与证据 |
| --- | --- |
| LRO 手臂的组命令写入失败或在队列中过期 | 报主机 CAN 写入失败，保留接口、CAN 帧 ID 和系统错误。常规七轴组帧的 ID 是 `0x8080`。失败的指令不更新最近成功发送时间或控制看门狗。 |
| 主机写入成功，某一轴没有及时回复 | 按总线和电机地址报告缺反馈或超时。主机成功写入只能说明 SocketCAN 接受了该帧。 |
| 7 号最后一次读数为 7，当前反馈已过期 | 当前状态报反馈超时。电机表将旧故障码标为上次读数，原始快照仍保留该值。 |
| 已核实协议，同一电机的新鲜有效帧带有非零故障码 | 显示该轴和原始故障码，阻止测试继续。多个驱动的报码各自保留地址。旧协议的 7 显示 DRV_ERROR，v1.03 的 7 显示 OTHER_ERROR。 |
| 失能请求发出或报错 | 显示请求结果和驱动反馈两个状态。仅在后端逐轴失能反馈确认后显示确认。模拟确认单独标明。 |

## 实现位置

- `motors/src/protocol/canfd/socket_canfd.cpp` 的 `transmit_checked` 将对应帧的写入结果返回 LRO 单轴 MIT、组 MIT 和使能调用。每次调用最多等待 30 ms 的主机写入预算。队列中超时的这条命令随后会被丢弃。现有发送失败重试最多三次。失能请求沿用原来的专用路径和反馈确认机制。
- `motors/src/drivers/lro/lro_motor_driver.hpp` 和 `factory_hmi/core/backend.py` 从同一个有效接收回调读取收帧序号、主机单调时间和原始反馈头。轮询只能读取这些证据。使能调用返回非零码时，还需核对使能期间的新帧、收帧序号和报码；证据不一致也会中止使能。
- `factory_hmi/models.py` 的 `MotorSample.feedback_issue` 供预检、手动控制、轨迹播放和限位检查复用。`core/playback.py` 在判断前保留当前这组样本，供故障处理读取。`core/fault_diagnosis.py` 跳过过期读数的电机故障、负载和温度推断。
- `factory_hmi/desktop/app.py` 的报警窗口保留网关原始地址和故障码。电机表在读数过期后标明来源，协议不明时只显示数字报码。`gateway/device_tools.py` 拒绝在手臂轨迹运行、暂停或手动控制期间打开共线灵巧手读取状态，并识别 Linux 返回的小写 `bus-off`。
- 现场核对时，保留同一次故障的测试阶段、接口、节点 ID、原始反馈头、协议、收帧序号、反馈年龄及同期 CAN 写入错误。收帧时间是上位机 SDK 处理帧的时间；驱动内部报警产生时间和电机是否执行一条命令仍需要另外的证据。

## 离线验证

用本地 Unix 套接字对替代 CAN 设备，在真实发送线程中注入故障。连续四次写入返回 ENOBUFS，调用方收到失败；下一帧成功写入；排队等待超时的命令在队列恢复后也没有写入。复现代码随原生 SDK 离线构建测试保留在 `motors/tests/socketcan_write_receipt.cpp`。

Python / Qt 两批合计运行 350 项，346 项通过。4 项在未修改的 v3.0.39 上也失败。其中两项预期首帧偏差在 Armed 阶段直接拒绝，当前逻辑会规划首帧接近过程。一项预期回默认位时一旦反馈过期便立即失能，原版可进入保护阻尼。另一项检查正常结束提示的旧文案。这些用例和结果保留于本地构建验证目录 `hmi/dist/can-feedback-diagnosis/`。

本次已验证主机端判据和原生 SDK。30 ms 的发送预算还需在实际工位负载下核对。本次未连接机械臂，未制作或安装现场更新包。
