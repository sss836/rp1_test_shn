# v3.0.32：新电脑的本地 109 升级资源

## 现场问题与根因

2026-11-16 的 A08 截图显示：平台下载提示“尚未配置信任电机固件公钥”；本机维护已识别五台 108 电机，但提示缺少签名 109 固件或 OTA 映射。两项都是资源配置缺失，不是未发现电机。

复核 v3.0.31 的 Ubuntu 22.04/24.04 发布包，均未包含电机固件公钥、OTA 映射和 `.lsepbin`。开发机用户目录中此前已手工导入这些资源，其他电脑/其他 Linux 用户没有相同缓存，因而不能升级。仅登录平台不能补齐信任公钥。

## 修改与连接关系

* `factory_hmi/bundled_motor_assets.py`（新增）：校验已批准的公开资源包，按当前用户状态目录原子初始化 `config/motor-firmware-public-key.pem`、`config/motor-ota-policy.json` 和 `data/motor-firmware/releases/`。无网络、CAN、PLC 或刷写动作。
* `launch.py::seed_configs`：启动 gateway 前调用上述初始化。原有 `gateway_environment` 把公钥和映射路径传递给 firmware download/maintenance 服务；安装在其他电脑或使用新的 Linux 用户，也具备同一资源。
* `tools/build_local_deb.py`：构建前及暂存后校验完整资源；缺失、文件损坏、额外未列入清单的文件均阻止出包。构建报告记录四型号及资源哈希。
* `pyproject.toml`：包含维护资源的 package-data。
* `tests/test_bundled_motor_assets.py`：全新用户启动、重复启动、保留专用信任配置、缺文件/篡改拒绝；11 个模块逐个验证单选/全选升级及 108/109/混装的既有控制链路。

公钥是已发布固件的验签公钥，不是私钥。资源清单的 SHA256 固定在源码中，初始化先核对全部文件及 Ed25519 签名，再导入。已有不同公钥或不同专用 OTA 策略不自动覆盖；启动日志明确报告保留专用配置。重复启动不覆盖测试配置、记录或已有固件缓存。

## 已批准资源

四型号：`LRO_5550`、`LRO_6562`、`LRO_8462`、`LRO_10062`。

共用固件：`L5N_RZT2L_CAN_CDH2_V5.0.0.109_202610281537_release.lsepbin`，501316 字节。

SHA256：`7277645da5e2d461e0339e87e21b5603abcb13065416fb416a1e279d48eb966a`。

已确认的源读回为软件 `0.1.8`、硬件 `0.1.0`、协议 `0.0.1.17`，无需再次要求用户确认“0.1.8 是否是 108”。`0x31` 完整字符串在旧固件上超时，不否定该已确认数值组合。目标为 `V5.0.0.109` / 软件 `0.1.9`。型号分别匹配签名元数据与既有产线参数，四型号共用固件文件不等于共用参数。

## 用户流程

升级上位机后重启，在原来的“样机配置与连接”应用模块、连接 CAN 并扫描。打开“电机版本/固件下载 → 108→109 升级/固件维护”，维护方式选“本机”，刷新版本后单选或全选 108，点击“更新所选”。离线维护不要求平台登录。

原有流程负责停测/失能检查、总线独占、串行写入及产线校验响应。所选电机全部写完后，一次人工重新上下电，再点击确认并统一回读。只写完不显示“版本验证通过”；回读未通过保持未通过。参数仍走已有产线脚本，按每台电机型号匹配，支持单选和全选。

测试操作页面与步骤未变。已有自动协议选择按每台电机的 108/109 身份使用原有换算表；109 原始 Iq、按实际读回 Kt 计算并明确标记的估算力矩，以及实时显示、曲线、峰值统计、CSV 均保留；108 原始力矩路径不变。不会因导入资源而自动更新电机或自动启动动作。

## 支持范围与验证边界

覆盖当前配置目录中的 11 种模块：左右 7 轴臂、左右 5 轴短臂、左右腿、左右短腿、腰胯、双腿腰胯组合、上肢组合。按真实配置文件的总线、ID、型号测试，而非只覆盖左臂 can0。

“任意模块”指这些现有模块和上述四款已确认 LRO 电机；未知型号/未知硬件组合不会通过强制放行刷写。

软件验证使用隔离状态目录、mock 电机和无硬件容器。安装验证与模拟动作链路不代表已在 11 种实体模块上完成现场刷写、带载动作或长时老化。最终构建、回归和容器结果见交付目录验证报告。

## 源码重建

二进制固件通过同版本 GitHub Release 的 `rp1-motor-assets-20261028.tar.gz` 分发，不提交到源码仓库。解压到 `hmi/factory_hmi/resources/motor-maintenance/` 后构建，构建器自动验证全部资源和源码固定的清单哈希；缺少资源时构建会失败，避免再次发布不完整安装包。

平台默认地址保持 `https://10.43.17.214:8443`。每个 Linux 用户的状态目录独立，默认 `~/.local/state/rp1-test-hmi/`。A08 需实际升级并重启新实例才能生效，不能仅以安装成功或平台登录成功判断资源已加载。
