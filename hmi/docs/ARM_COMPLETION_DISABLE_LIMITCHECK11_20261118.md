# 手臂收尾与逐电机失能

安装版原逻辑存在三处确定缺陷：`MotorBackend.disable_motors` 发完命令立即 `_enabled=False`；`MotorsPyBackend._disable_impl` 只调用 unlock，不逐台核对；下一次失能若遇到 `_enabled=False` 会提前返回。原生 `LroMotorDriver::unlock_motor` 的109分支调用 `try_transmit`，失败未转成Python异常。它允许出现“Python调用没抛错，而设备尚未执行”的情况。模拟丢弃最后三台首条命令能复现状态矛盾，但现场究竟是队列拒发、CAN丢失或设备未执行，仍需原始总线证据，不能仅凭本次快照归因。

## 数据与状态边界

正常四臂路径：整轮检查 → 退让/回零 → 肘部缓降 → 新鲜反馈连续停稳 → 逐台失能确认 → 保存报告。故障/操作员中止走原失能路径，不为完成外观再追加运动。完成下垂仅表示运动完成，不等于驱动失能确认。

记录保存于原本本地会话 `limit-checks/` 目录，追加收尾实测角/速度、资源证据和失能明细。旧报告与测量事实不修改；不自动上传正式测试数据，不更改平台提交/核实/审批规则。UI只读取小状态，完整样本只在导出读取，反馈窗口有界；重试在原任务/关闭工作路径执行，不在Qt主线程执行CAN等待。

## 验证边界

隔离测试覆盖：四臂镜像缓降/实测停稳/静态MIT偏差、任务间模板独立、控制循环预热时序；七台末三台首发丢失重试、旧缓存/延迟/异常/部分成功、混装108/109、重复失能及确认代次；普通只读释放、严格维护、可信隔离RPC与句柄生命周期；UI逐台状态与报告导出。具体命令、通过数与跳过原因保存在交付目录。

没有自动执行真实CAN/PLC动作。模拟、包内启动及安装成功均不等于真实下垂承重、逐台关断或长时现场验收。
