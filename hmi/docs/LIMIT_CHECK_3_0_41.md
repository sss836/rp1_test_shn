# 3.0.41 限位验证与故障处置

## 故障后的动作

3.0.40 的限位线程在退出时直接请求全部电机失能。3.0.41 为可以继续信任反馈和发送通道的限位软件故障增加保护阻尼交接。控制器确认限位线程仍拥有当前控制代次、原位置保持已完成交接，并在开始阻尼前重新检查逐轴反馈。常规回放和其他功能继续采用原阻尼参数。

| 触发条件 | 上位机的处理 |
| --- | --- |
| 具名的检查软件故障，例如旧试点的跟踪超差；反馈组间隔超限后所有轴均重新给出更晚的新鲜反馈 | 停止推进轨迹，尝试接管现有使能。成功后使用绝对 Kd=2.0，Kp、目标速度、前馈力矩均为零。报告记录交接时状态、原故障和中止阶段。 |
| 驱动报警、过温、关节或电机过载、工装边界越界、链路持续劣化、反馈或命令无法核实 | 走失能路径，保留请求与反馈结果。保护阻尼开始后继续核对电机身份、反馈时效、温度、速度、实测及按当前速度估算的阻尼力矩。发送前重新检查控制权、停止标志和反馈截止时间。 |
| 正常完成、明确中止或失能、急停 | 原处置继续执行。已失能的电机不会因为一次旧限位故障被重新使能。 |
| 全行程准备、基线、退让停稳或手臂收尾等待满 30 秒 | 在界面显示阶段等待告警并保存至报告。等待本身不触发失能或阻尼。 |

阻尼依赖驱动供电和可用的 CAN 通信。纯速度阻尼在静止时没有保持力矩，实际下降轨迹、速度、力矩和机械间隙均须结合工装、负载和支撑条件验收。软件不把发出阻尼或失能请求记为已确认机械承重。

## 立柱工装、腰部和记录

- 已有核定的五轴左腿立柱方案继续使用工装专用顺序、膝姿态、髋内摆 −20° 截止、实测越界保护和退让。原 5 ms 周期及 60/40°/s 提速暂停，按 25 ms 最小命令间隔、转场最高 20°/s、远端搜索最高 10°/s、近限位最高 2°/s 执行。普通内置左腿方案缺少工装专用内摆截止，不能替代立柱方案。3.6 mm 是模型估算值。
- 腰部保持髋轴的位移相对进入检查时的实测角判断。默认 0.2°，中止消息给出轴名、起始角、实测角、带方向位移及门限。工位核定方案可用 `waist_hip_hold_drift_deg` 指定位移门限。调整需要具名核定人的腰部 site 方案及两轴的 `waist_hip_hold_bounds_deg`，实际角也受各自绝对范围约束。
- `ProbeWorker` 的接收诊断和记录复用同一份电机字典。搜索延期配置复用静态内容，动态力矩、故障与角度随帧记录。每个方向完整保留最近 5000 帧。更早的记录按可核对的步长保留最多 511 条，报告字段为 `earlier_samples`、`earlier_stride` 和 `evicted_from_full_resolution`。末端数据与早期概览分开标记。
- 检查层共用同一间隔诊断格式，注明阶段、实测间隔、门限及来源。单电机反馈年龄、组完整性、持续缺帧和力矩保护仍分别执行。偶发漏帧的原目标补询沿用 3.0.40。

## 电机身份

连接时仍完整读取身份，以便发现换件或与工位记录冲突的固件。对配置摘要、CAN、ID、型号及数值身份均符合本地核定记录的旧协议节点，本次连接已确认 0x31 超时后，同一连接后续刷新仅重读 0x1E。数值身份必须由本次有效原始响应核实。纯超时保留原证据时间，身份变化拒绝继续沿用。109 的 Kt 固定在本次使能；待机和运动均无 60 秒轮询。

实现分别位于 `core/live_limit_probe.py`、`core/module_limit_check.py`、`core/controller.py`、`core/protective_damping.py`、`core/backend.py` 和 `core/motor_versions.py`。本版通过软件注入和模拟工位验证；现场安装状态、包哈希和发布回执另见交付目录。
