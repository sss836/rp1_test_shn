# 模块固件维护（第1版，第3阶段）

此入口使用当前实例已应用的 StationConfig，承接实际版本读取与独立电机固件缓存。下载不启动刷写。用户进入“电机版本 / 固件下载 → 模块固件维护”，选择全部或部分目标及已下载固件，核对模块、关节、最终接口、ID、型号、OTA请求/响应ID、当前与目标版本、SHA256、签名兼容来源，再明确确认启动。

## 顺序与状态

1. 当前真人账号必须是执行员或管理员，网关会通过现有 `/api/v1/auth/me` 核对；服务账号、只读账号、退出或账号变化拒绝维护。窗口使用当前配对 session 的控制租约，不能以另一窗口租约操作。
2. 必须先停止测试并失能，结束位置保持、归零与测试收尾，CAN接口已按有效配置就绪。软件状态不是实际失能反馈；现场人员仍须核实设备安全条件。本入口不控制PLC或供电，不自动配置CAN，不调用使能或运动。
3. 预览有效期120秒。配置内容哈希、账号、签名固件和兼容映射在启动时重新核对；界面改选会撤销预览。最终配置支持平铺、`motors`嵌套及界面bus/ID/model覆盖；冲突包裹、重复接口+ID、未知型号与非LRO/CAN-FD目标拒绝。OTA ID为 `0x1000 + 2*motor_id - 1`，响应为请求+1。
4. 后台仅一条串行维护线程。本机维护批次互斥，包括不同总线；当前后端停止版本轮询并保留总线资源，其他实例或控制打开不得争用。写前重新读取0x31、0x1E实际版本，验证当前身份及兼容性，再握手、擦除、逐块发送、自校验。握手仅一次、不自动重试、不自动复位。单台总预算300秒，取消在协议收发与块边界检查。
5. 每台写完进入 `awaiting_power`。弹窗“请重新上下电”，人员操作，界面单独记录人工确认账号/时间；这不是供电检测，不能称已核验。用户再点“单独回读实际版本”，读取原始完整字符串、软件、硬件、协议并比较目标；匹配后才继续下一台。未知、超时、版本不符、错误响应或中断都停止后续目标，未做目标标 `not_run`。
6. 失败可能已擦除或部分写入，不承诺回滚。需要人工检查记录与设备状态，再重新预览并明确发起新任务；禁止盲目重试。取消、租约失效、退出/切换账号和服务关闭先通知并等待维护线程，超时保留占用，不强杀或解除锁冒充关闭成功。维护提交与登录/退出共用账号切换互斥边界，锁顺序为账号→租约→服务→任务；后台线程和控制心跳不获取账号锁，退出扫描不能漏掉并发启动。

## 签名兼容映射与未知边界

固件仍使用独立 `rp1-motor-firmware-v1` 发布契约及Ed25519公钥 `RP1_MOTOR_FIRMWARE_PUBLIC_KEY`，缓存从 `motor-firmware/releases/<release_id>/` 读取。预览和写前验证清单签名、类型、长度、SHA256、型号/硬件/协议/精确from_versions，写入使用验证后的同一份bytes，不能混用DEB。

`108`不自动等于`1.0.8`。管理员须根据厂商/维护证据提供精确映射，经 `tools/prepare_motor_ota_policy.py --metadata <JSON> --private-key <管理员私钥> --output <新文件>` 签名，再在本机配置 `RP1_MOTOR_OTA_POLICY=<已签名文件>`。工具仅签名准备，不发布、不部署、不刷写。私钥仅管理员持有，禁止进仓库或包。策略使用同一可信电机固件公钥；这个部署动作须有具体授权。

元数据结构：顶层 `schema="rp1-lro-ota-compatibility-v1"` 与 `entries` 数组。每条严格包含 `model`、`hardware`、`protocol`、`raw_version`、`software_version`、`ota_protocol="lro-canfd-xcp-v1"`、`evidence_url`（HTTPS）、`evidence_sha256`。按实际原始字符串、型号、硬件、协议精确匹配；软件数值版本必须与实际0x1E相同且至少1.0.8，目标软件版本更高。重复映射拒绝。证据哈希指厂商/维护来源，不是凭文件名猜出的版本。签名仅证明管理员确认的数据来源，不代替厂商内容和真实设备兼容验收。

仓库及安装包不附带任何可用于真实设备的兼容映射或固件。无真实适用证据时仍可查看版本和下载，但维护预览拒绝。

参考OTA模块原先接纳 `FF 02 02` 暂定放行。本入口严格接纳 `FF 02 01`，保存原始失败响应，`02`语义未核实前拒绝，且即使01通过也不等于实际版本核验通过。不发送参考模块的自动reset命令；仅提醒人员重新上下电。

## 记录、恢复与运行边界

每个实例的 `<data_root>/motor-maintenance/<job_id>.json` 以原子替换和fsync持久化，保存配置哈希、账号/会话、目标、发布与来源元数据、固件SHA256、映射哈希、写前版本、写入字节数、协议回执、人工确认与独立回读。块进度最多每250ms落盘，收尾/状态转换立即落盘；突然断电时最后少量进度可能尚未落盘，状态会标中断未核验，不能据此推断设备实际写入量。全局串行锁与后端总线占用必须保持到终态保存及资源关闭成功。终态保存或关闭失败会显示收尾失败并保留占用；再次显式取消或关闭仅重试报告保存和资源关闭，不重放设备写入。记录仅本地保存，本阶段不自动提交业务统计或云端归档。

启动读取未完成任务时标 `interrupted` / `interrupted_unverified`，其他目标 `not_run`，不恢复写入。历史完成回执保留；服务会返回当前会话最近加载的中断记录或本次任务，其他账号不显示前账号任务详情。读写维护、人工声明和设备回读都独立于测试数据审批。

源码链路：`core/config.py` → `core/service.py` / `core/backend.py` → `core/motor_maintenance.py` → `core/motor_ota_transport.py`（只复用已入库 `motors/scripts/motor_ota.py` 的组帧及命令原语），经 `gateway/motor_maintenance.py` 验证会话、缓存与策略，`gateway/app.py` 提供 `/api/v1/motor-maintenance` 及preview/start/acknowledge/readback/cancel，`client.py` 和 `desktop/motor_maintenance_dialog.py` 展示状态。诊断助手不发起维护写入。

本阶段交付为软件与候选包。模拟协议、Qt offscreen与隔离ASGI结果不等于真实CAN-FD、厂商兼容、断电持久化或现场验收。新包未安装和运行时不能称已生效；安装必须按仓库AGENTS.md核对测试停止、实际失能、PLC总停止、正常退出及同状态目录新实例。
