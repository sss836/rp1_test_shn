# 5 自由度腿真机限位搜索试点

试点在上位机「限位块检查 → 真机试点」。本地候选包以 v3.0.32 为基线，默认保留「模拟验收」。真机先开放左右 5 自由度腿，并限定为已核定的独立外部供电工装。单臂和腰部仍留在模拟验收，待此试点实机通过后再接入；腰部范围固定为腰侧摆和腰旋转，各自查上下限。

## 现场核定表

基准为用户提供的 RP1.3.4 量产表（20260916）角度列。以下是比对参考，用机构、工装、装配版本逐项确认。实际搜索需要单独确认近端姿态、推进余量和载荷。

| 逻辑关节 | 左腿下限／上限（°） | 右腿下限／上限（°） | 默认电机 ID |
| --- | ---: | ---: | --- |
| 髋侧摆 | −42.73／149.87 | −149.87／42.73 | 3 |
| 髋旋转 | −157.8／157.8 | −157.8／157.8 | 4 |
| 膝屈伸 | −162.86／2.14 | −2.14／162.86 | 5 |
| 踝俯仰 | −45／35 | −45／35 | 6 和 7 |
| 踝侧摆 | −15／15 | −15／15 | 6 和 7 |

每条关节方向单独填一行。五轴逻辑向量顺序为髋侧摆、髋旋转、膝屈伸、踝俯仰、踝侧摆。五台**电机**向量按当前实际生效配置的节点顺序填写。

| 核定内容 | 方案字段 | 填写方式 |
| --- | --- | --- |
| 工装和校准身份 | `fixture`、`revision`、`approved_by`、`station_sha256` | 写清夹具编号／修订、核定人及上位机显示的实际配置摘要。摘要对机型、CAN、ID、零偏、方向、型号及基础 Kp/Kd 生效。 |
| 复位起点和搜索起点 | `staging_pose_deg`、`search_pose_deg` | 各五个角度。其他四轴固定在已确认无干涉的姿态。搜索起点位于参考限位内侧，复位历史默认 4 秒，按核定的定位速度放慢。 |
| 搜索行程和角速度 | `permitted_travel_deg`、`search_speed_deg_s`、`positioning_speed_deg_s` | 从搜索起点向选定方向的总指令位移。明确写出允许的参考外试探余量。软件限额为总推进 ≤12°、参考外 ≤3°、搜索 ≤1°/s、定位 ≤5°/s、单次搜索行程对应 ≤45 秒。这些是拒绝越界的上限，核定时需按工装填写更具体的值。 |
| 复位和搜索 Kp/Kd | `reset_kp_scale`、`reset_kd_scale`、`search_kp_scale`、`search_kd_scale` | 核定时记录每台电机的**实际指令增益**。以现有配置增益乘核定倍率，页面显示展开后的每台电机值。标准 YAML 的髋侧摆、髋旋转和膝为 110／4，踝两电机为 40／2；现场生效值以当前配置为准。倍率 ≤1，Kp 必须为正、Kd 可为 0。 |
| 候选接触门限 | `contact_floor_nm`、`contact_rise_nm` | 搜索增益稳定后测力矩基线。窗口内最小绝对力矩需同时超过下限和基线增量，且连续 1 秒角度跨度 ≤0.2°、指令还在推进。 |
| 中止力矩 | `motor_abort_nm`、`joint_abort_nm` | 两列各 5 个 N·m。电机侧任何节点及逻辑侧任何轴达到门限即停止推进并请求失能。踝侧逻辑门限要分别核定俯仰和侧摆，两台电机各自也保有独立门限。候选阈值必须与中止门限留出余量。 |
| 跟踪与缓退 | `following_error_deg`、`motor_step_deg`、`retreat_deg`、`comparison_tolerance_deg` | 明确最大跟踪偏差、每次电机指令可变化角度、净退距离、允许候选偏差。路径须允许沿刚才的运动反向缓退。 |
| 现场撤力条件 | 独立外部供电、支撑、物理急停 | 先核对机构在本方向停搜或失能后可由工装承托，验证急停和驱动实际失能。软件发出失能指令与设备回读是两个状态。 |

搜索到达核定行程时即停。若余量内没有足够时间形成候选证据，输出「未检出」，所以现场要同时核定推进距离、速度、跟踪误差与候选窗口。视频、测试夹具里的数字为合成数据。

## 接入和执行

1. 在正常上位机应用对应纯单腿配置并连接 CAN、扫描。真机页按上下限选择当前方向，填实际样机编号，读取核定方案并看摘要，再单独使能。
2. 管理员核定完成后，按实际腿部将该方案登记到 `/etc/rp1-factory-hmi/limit-probe.d/left_short_leg.json` 或 `right_short_leg.json`。目录、文件必须属于管理员且普通用户无写权限。当前提供留空的编制模板，不携带可执行的预填控制值。摘要不匹配、配置改变、缺方案或缺逐电机可用的力矩证据均拒绝开始。
3. 复位使用位于核定起点附近的实际姿态。发送平滑目标后，还需通过回读停稳。点击「开始搜索」后，程序在起点平滑过渡到搜索 Kp/Kd 并采集基线。
4. 单个逻辑方向推进。收到候选或达到行程上限，就撤掉继续推进的目标，沿刚才连续的实测路径缓退。实退到位后结束这一方向并请求失能。反馈异常、超力矩、跟踪偏差、退路不足、租约失效或中止动作触发停止链路。每个方向分别复核、另行使能和开始。
5. 导出的本地 JSON 保留配置摘要、工装、样机、参考角、候选角、偏差、净退距离、阶段、原始驱动反馈和 108／109 力矩来源。报告仍留 `calibration_passed=null`，现场记录用于安装复核。

执行由 `core/live_limit_probe.py` 的 `ProbeCycle` 和 `ProbeWorker` 在原独立工位进程内完成。`core/service.py` 核对工位有效配置、方案摘要、路径和现有限位。`core/backend.py` 对试点拒绝仅靠缓存或应答次数兜底的快照，要求逐节点原生收帧序号和协议。108 使用已确认驱动回读，109 使用实际 Kt 与 Iq 的估算力矩；踝部通过现有闭链映射换算逻辑角度和力矩。

网关端限制本机维护授权、有效工位租约和 CAN 独占，搜索占用时挡住普通运动与维护指令，沿用中止、失能及工位关闭。桌面只发独立操作并每 500 ms 查询状态，控制线程约每 25 ms 查看逐电机反馈，未收到全部更新时暂停发新目标。连续等待至 150 ms 即从运动链路退出并请求失能。界面不依赖统计或平台网络。

## 验证分界

当前已完成软件和模拟验证。MuJoCo 视频使用同一状态机的模拟角度数据，显示左膝正常与提前阻挡、左踝俯仰下限正常与未检出。视频是姿态重放，力矩由模拟反馈合成。现场仍须用核定参数完成左／右腿正反方向、踝闭链、负载与撤力，以及急停和中止反馈的实机验收。通过前不扩到单臂和腰部。
