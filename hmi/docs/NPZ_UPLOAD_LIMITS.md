# NPZ 轨迹上传：1 GiB 上限与流式接收

2026-10-19：按用户选择，将单文件上传默认上限由 128 MiB 调整为 **1 GiB（1,073,741,824 字节）**。
本说明对应候选包 `2.0.11+ubuntu24.04.lease1.npz1`；它是已有 `2.0.11+ubuntu24.04.lease1` 的最小更新，不包含工作区其他待完成的平台和 HMI 改造。

## 当前功能与边界

- 桌面“导入轨迹”仍接收 `.npz`，空文件仍被拒绝；大小合格不等于轨迹内容、模块或安全预检合格。
- 文件从桌面发送给 HMI 网关，并保存在工位本地；这不是向 Reliability Platform 归档采集 CSV 的接口。
- 默认目录为 `~/.local/state/rp1-test-hmi/data/trajectories/`；自定义状态目录时以实际状态目录为准。
- 收到的文件长度和实际累计流量均受限，超限返回 HTTP 413。缺失 Content-Length 的流式请求也检查实际累计大小。
- 上限可配置，界面没有新增设置入口。默认 1 GiB，显式设置 0 才取消固定文件大小上限。
- 上传阶段避免客户端和网关各自额外持有一份完整文件；后续 NumPy 解压、数组复制和预检仍需要内存。1 GiB 是上传文件上限，不是内存占用上限或对所有 1 GiB 文件解析成功的保证。

## 文件与实现

| 文件 | 修改内容与连接关系 |
| --- | --- |
| `hmi/factory_hmi/gateway/trajectory_upload.py`（新增） | `configured_trajectory_limit()` 读取配置；`receive_trajectory()` 校验声明长度、累计分段大小，并在线程池中写入唯一 `.part` 文件。失败或断传时删除临时文件。 |
| `hmi/factory_hmi/gateway/app.py` | `create_app()` 固定本次启动的上限；`/api/v1/trajectory/upload` 接收完成后在线程池中执行既有解析，控制租约检查保留。同名旧文件在替换解析失败时恢复；成功后才移除旧文件的临时保留副本。 |
| `hmi/factory_hmi/client.py` | `GatewayClient.trajectory_upload()` 将打开的文件流交给 urllib，发送真实 Content-Length；请求结束或异常时关闭文件。上传专用套接字等待超时默认为至少 120 秒，普通控制请求仍使用原超时。 |
| `hmi/launch.py` | `gateway_environment()` 显式保留两个 NPZ 配置变量，避免启动器清理设备环境变量时把设置丢掉；其他设备配置变量的隔离规则保留。 |
| `hmi/tests/test_trajectory_upload_limits.py`（新增） | 覆盖默认值、配置校验、分段超限、断传、空文件、长度不符、129 MiB 实际接收、同名恢复、客户端文件关闭及启动器配置传递。 |
| `hmi/tests/test_factory_hmi_client.py` | 更新上传断言，在请求期间读取流，并检查请求结束后已关闭文件。 |

流程为：选择本地 NPZ → 后台线程发起文件流 HTTP 请求 → 网关分段保存唯一临时文件 → 再次核对控制权 → 原子替换并执行原有解析/预检 → 返回结果和状态。
上传失败不自动重传，也不会自动使能或开始回放；排除错误后可重新导入。当前是重新上传，不是断点续传。

文件写入和解析不在 ASGI 事件循环中执行。桌面原有心跳定时器、请求完成回调、pending 清理与 2 秒控制租约策略保持；大文件上传不授予无限续租，也不放宽电机反馈和 PLC 保护。
文件解析仍沿用原有控制器与租约锁，不能把本次上传改造描述为所有控制操作的延迟问题已经解决。
成功日志记录文件名、字节数和本次生效上限，不逐块打印日志。

## 使用配置

新包不设环境变量时就是 1 GiB。需要明确指定时，先按现场流程确认测试停止、电机失能、PLC 正常总停止实际反馈，再正常关闭旧 HMI，确认同一状态目录的 `rp1-test-hmi status` 返回 `running=false`。安装、核对版本后再启动：

```bash
RP1_FACTORY_TRAJECTORY_MAX_BYTES=1073741824 rp1-test-hmi
```

需要更长的上传/解析响应等待时间时，可同时设置秒数：

```bash
RP1_FACTORY_TRAJECTORY_MAX_BYTES=1073741824 \
RP1_FACTORY_TRAJECTORY_UPLOAD_TIMEOUT_S=240 \
rp1-test-hmi
```

以上变量作用于此次启动。已有实例不会因再次运行命令而切换设置；必须先正常关闭原实例。上传专用超时不是总执行时间的硬期限，更不改变控制命令的超时或保护逻辑。

不建议直接编辑 `/opt` 内已安装文件来临时修改数字，因为这会破坏包清单一致性，而且旧运行进程可能继续使用已加载代码。
