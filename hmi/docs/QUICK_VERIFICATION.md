# 工厂快速验证与新开窗口

## 使用

左侧“＋ 新开窗口”启动独立桌面和工位进程。两个窗口使用不同的工位身份及 CAN 占用，共用本机网关、PLC 配电柜进程和平台登录。关闭窗口时先核对本工位释放回执。

进入“工厂快速验证”，点击部位后自动读取网关当前的标准电机配置（包含已配置的零偏、KP/KD、控制频率与 CAN 位率）和随包内置的 NPZ。读取阶段不供电、不扫描、不使能。该步骤会预约所选 CAN，其他窗口正在占用时明确拒绝。

选择“供电方式”：新界面默认“外部供电”，也可以选择“PLC 供电（自动控制）”。点击“运行…”，填写循环时间（小时）并确认现场支撑、运动范围与物理急停安全；外部供电还需确认外部电源已接通。随后按顺序执行：

1. 外部供电模式直接进入 CAN 与电机流程，其启动和运行监控不要求 PLC 在线、控制权限或通道许可，也不发送快速验证的 PLC 供电命令。外部电压/电流由外部电源设置。PLC 供电模式则核对本机 PLC 可控制、通信有效；若 OFF，按默认参数打开对应通道，若已运行，只打开缺少的通道，不改变已有通道/电源设定；等待实际反馈确认，故障或超时不自动重发。网关原有的独立 PLC 页面和背景监控保持原架构。
2. 连接 CAN，扫描电机并使能。
3. 以实际反馈核对首帧和限位。需要时按当前反馈缓慢接近轨迹首帧，再确认位置与速度稳定。
4. 按固定 1 倍速循环，按有效运行时间累计小时数。暂停时间不计入运行时长。

达到设定时长或点击“正常结束测试”后，已开始的测试补完当前一圈再收尾。暂停中申请正常结束会保持暂停，点击“继续”才补圈。测试尚未开始循环时，结束请求取消准备。软件失能和故障保护保留抢占路径。

快速验证和普通轨迹测试共用 `core/playback.py` 的启动逻辑。轨迹文件的峰值速度仍计算并可查看，不再单独作为拒绝启动的条件。关节和电机位置限位、相邻帧变化限制，以及有已核实工位参数时的加速度和制动空间检查仍有效。首帧接近和收尾继续按原限速与到位判据运行；实际反馈超速仍会触发运行保护。

四种手臂默认按 MuJoCo 下垂收尾。启用该选项须在每次运行前确认模型姿态适用且到位后可安全撤力。取消勾选可按工位配置收尾。腿和腰髋按已核实的工位参数收尾。收尾到位并确认反馈稳定后失能，原始记录写入结束后再断开本窗口 CAN。缺少已核实参数时保留位置，未能确认到位稳定时保持并提示。外部电源由现场管理，共用 PLC 柜的总停止由独立配电柜流程处理。

快速验证始终记录在本机，无需登录平台。工厂模式须填写实际台架，可自由填写样机标识。研发模式的在线样机目录可用时，选用当前部位已登记且未运行的样机。进入正式统计须走核实、显式提交和审批流程。

## 部位、内置原始轨迹与默认 CAN

| 部位 | 默认测试项目 | 轨迹 | 默认接口 |
| --- | --- | --- | --- |
| 左臂 7 DOF | `UNIT-AGING-006` 左臂老化 | left_arm_joint_inspect.npz | can0 |
| 右臂 7 DOF | `UNIT-AGING-007` 右臂老化 | right_arm_joint_inspect.npz | can1 |
| 左臂 5 DOF | `UNIT-AGING-004` 左短臂老化 | left_short_arm_joint_inspect.npz | can0 |
| 右臂 5 DOF | `UNIT-AGING-005` 右短臂老化 | right_short_arm_joint_inspect.npz | can1 |
| 左腿 5 DOF | `UNIT-AGING-001` 左腿老化 | left_short_leg_flow.npz | can0 |
| 右腿 5 DOF | `UNIT-AGING-002` 右腿老化 | right_short_leg_flow.npz | can1 |
| 腰胯 4 DOF | `UNIT-AGING-003` 腰髋老化 | waist_hip_joint_inspect.npz | 左 can0、右 can1 |

腰胯 NPZ 的四列顺序沿用原文件：右侧腰 roll ID1、左侧腰 yaw ID1、右髋 pitch ID2、左髋 pitch ID2。因此配置分组 CAN 为 `[can1, can0, can1, can0]`。同侧两个电机必须在同一总线，左右总线必须不同。界面可以选择 CAN；修改后点击“重新读取配置与轨迹”才生效，避免把尚未应用的映射直接用于运行。

七条工厂资源均原样保存所选源文件内容，使用 `factory_hmi/resources/quick/manifest.json` 记录 SHA256，运行前校验完整性。只允许通过预设 ID 读取这些固定资源，不放宽普通轨迹导入的目录限制。源码和本地 DEB 均包含轨迹；Python 包的 package-data 也包含相应资源。

## 实现与生命周期

- `quick_profiles.py`：本地目录、部位和 CAN 分组映射、资源哈希校验。
- `gateway/quick_run.py`：`QuickRun` 串行执行准备流程；沿用网关模块租约、CAN 互斥、PLC 指令协调器、正常回位与预检。异常停止后清理本窗口；清理失败保留 CAN 归属，避免直接交给下一窗口。
- `gateway/app.py`、`gateway/schemas.py`：快速验证读写沿用本地操作令牌与每窗口租约。运行时长须为有限正数。界面显式传入 `power_source` 和 `completion_mode`。API 未指定供电时默认 PLC。未指定收尾方式时，手臂默认 MuJoCo 下垂且须显式确认停放姿态，腿和腰髋使用工位配置。
- `desktop/quick_page.py`：七组部位入口、可修改 CAN、时长/安全确认弹窗、运行/暂停/继续/结束及状态展示。状态每 500ms 读取，最多一个状态请求在途；本地 RPC 在线程池，主线程不等待回位。离开页面不停止运行，关闭窗口停止计时器并按原失能/租约机制收尾。
- `desktop/app.py`：接入快速页及新窗口按钮，新增窗口使用独立 client_id，确认工位释放后关闭。
- `client.py`：快速准备/状态/运行/结束调用。启动请求单独使用 120 秒超时，结束使用 15 秒；不修改客户端公共 timeout，从而不延长独立心跳请求。HTTP 4xx 明确拒绝时保留原始原因，避免再次结束覆盖报错；网络未确认或 5xx 时发出取消请求并保留原始原因，不自动重发。
- `core/service.py`：后台报告线程在创建时持有本次 playback 对象。自动断开或重新配置清除 controller.playback 后，仍从原对象读取最终时长与结束原因；不改写已封存历史数据。

准备过程持有原模块指令锁，结束通过现有 motion epoch 与取消信号抢先中断。每次运行有一个本地 watcher 和独立停止事件，每 100ms 检查租约及运行状态；准备时心跳过期可取消长时间回位，运行时也核对 PLC 实际许可。一次运行结束后 watcher 退出，新的运行使用新的事件，旧 watcher 不得清理新运行。

PLC 心跳/反馈轮询、窗口租约心跳、快速页状态轮询和平台心跳分别沿用各自链路。快速状态只读取短元信息，不必等待电机快照；每个阶段有本地日志 `quick verification: owner=... phase=... detail=...`，相同状态不重复打印。PLC 自身确认时限以现有配置为准，不将 HTTP 收到应答当作物理确认。

## 数据与审批边界

每次开始的快速验证生成独立执行号，记录 20 Hz 原始 CSV。测试项目编号按部位固定，已有 `QUICK-*` 历史记录可按原编号读取和导出。供电方式写入 `QUICK_EXTERNAL` 或 `QUICK_PLC` 阶段和运行请求。正常结束、主动中止和反馈故障后的采集按现有流程封存。

封存的 `config/execution.json` 保存请求时长、速度、循环与收尾设置、实际时长、圈数、结束原因、收尾状态和故障。摘要从原始样本计算采样质量及逐关节温度、力矩和跟踪误差，可在本地执行记录和标准 CSV 导出中查看。回位发生在循环采集边界之后，位置与失能确认保留为独立收尾证据。数据核实和审批仍走专用归档入口。

在“老化测试 → 本地执行记录”可按样机及工位查询，或打开所选执行的本地目录。配电柜等待另一个工位的通道指令回执时，快速验证持续核对本工位的启用请求和实际供电许可。主电源或本工位许可丢失仍走本工位保护流程。

补圈与记录改动以 v3.0.26 为基线。Ubuntu 22.04 容器和 Ubuntu 24.04 本机隔离验证均覆盖独立模拟工位的完整左臂轨迹、MuJoCo 收尾、失能、CAN 释放及本机 CSV 封存。现场两腿与腰髋的实际停放位置、到位容差及撤力反馈需要按工位核实。

启动峰值检查改动使用 Ubuntu 24.04 的 mock PLC 和模拟电机验证。快速验证网关 22 项通过，含文件峰值超限仍完成一圈、回位失能，以及回位接续超速时在使能前拒绝。普通轨迹回归确认文件峰值不再阻止启动，实际反馈超速仍进入故障，已核实的加速度和制动空间检查仍生效。扩大回归 140 项通过；另有 5 项关于故障后立即失能、历史报告路径及首帧偏差的断言在改动前的 `7e1e37a` 同样失败。

真实设备验收应核对部位、电机 ID 与接线，尤其是腰胯映射。软件 mock 回归、NPZ 校验和界面预览均不代表已完成 PLC/CAN 真机联调。

## quick2 修正

quick1 曾将 PLC 供电作为所有快速验证的必经步骤，外部供电场景也会因 PLC 不可控制而被拒绝；同时界面把明确拒绝再次转成结束请求，覆盖了失败原因。quick2 增加外部供电选项并修正失败显示，原始 failure 和 failed_phase 会保留到下一次重新准备。


2026-10-28 工厂资源清单升级为 v2。左右 5 DOF 资源原样取自对应短臂 NPZ。来源路径、哈希和资源修订见清单。两文件均为 633 帧、50 Hz、12.64 秒，首尾电机命令为零。实际停放位置和撤力条件由所选收尾方案及现场确认确定。
