# 模块参数读取与写入（第4阶段软件候选）

此候选实现 KT、MIT 编码范围、CAN 超时，以及已发布脚本兼容模板中 Pn 的独立读取、比较及经确认逐项写入。旧 v1 模板仍不授权 Pn 写入；v2 `lro-pn-script-v1` 仅在精确型号和完整版本匹配时使用单请求时序关联。回包不回显 Pn 编号，此限制不因软件接入消失。未安装、未部署，不能视为真实设备验收。

## 候选表与发布

`factory_hmi/resources/motor-parameters/candidates-v1.json` 使用 AST 读取固定 SHA256 `34f2214d52cf5e879e9ec169ec91725b22cdc99228a47d2671a491c9c85b0f3c` 的 `deploy_motorlro_params.py`，不导入、不执行脚本。包含四种 LRO 型号、KT、编码范围 KP/KD/POS/SPD/TOR/CUR、CAN_TIMEOUT 和脚本适用 Pn，全部 `confirmation=null`、`applicability=[]`。候选不自动发布。

编码范围 KP/KD 与 StationConfig 的运行增益相互独立。CAN_TIMEOUT 的候选 0 表示关闭保护，不能据候选直接认定适用或安全。KT 的电流定义、Pn 原始值量纲、型号和固件适用性均须由管理员依据厂商资料确认。

管理员整理候选 JSON 单个 `templates[]`，另建正式 `template_id`（32位小写十六进制）和 `version`，填写精确适用元组 `raw_firmware/software/hardware/protocol`，以及 `confirmation.evidence_sha256/notes`。可删除未确认或尚不支持的条目，形成明确范围的模板；不能把删除的项目记为已通过。每项使用原始整数 `expected_raw` 和绝对原始整数容差 `tolerance_raw`。固定单位、比例、可用编号由代码契约约束，不能上传表达式或任意 CAN 帧。

平台仅在配置 `MOTOR_PARAMETERS_ENABLED=true`、`MOTOR_PARAMETERS_ROOT=<仓库外独立持久目录>` 后启用。管理员 HUMAN 会话调用 `POST /api/v1/hmi/motor-parameters/templates` 发布。执行员/管理员 HUMAN 会话通过 `GET .../templates?model=...&hardware=...&protocol=...&software=...&raw_firmware=...` 查询。执行员不能发布或修改模板值。发布记录包含实际发布账号、时间、请求号和模板内容 SHA256。编号和型号/版本不可覆盖；相同内容重传幂等，变化必须新版本。文件锁、临时文件、fsync 和原子替换保护并发发布；模板完整性失败明确拒绝。此功能不涉及采集 CSV、归档或统计审批。

未执行任何正式发布。软件检查中使用的管理员和兼容元组均为合成样本。

## 上位机操作

在“电机实际版本与固件下载”中打开“模块参数读取 / 比较 / 写入（独立入口）”。

1. 停止测试并失能，保持 CAN 已就绪；维护不会使能、配置接口、控制 PLC 或供电。
2. 读取最终有效模块目标（包含界面总线/ID/型号覆盖），查询各目标的管理员已发布适用模板。选择全部或部分目标。
3. “独立读取并比较参数”仅查询。界面及 JSON 报告显示实际/参考值、单位、容差、模板版本/哈希、来源、响应、时间、目标和状态。未知、超时、跳过、归属未核验及零项均不算通过。
4. 读取完成后“预览实际旧值与模板新值”，再明确确认逐项写入。旧值及预览均限120秒；账号、有效配置、模板变更拒绝。写前重新读取实际版本和每项旧值；不同则停止。每项写入前先落盘，再发送并即时查询验证。只有本项通过才进入下一项，失败或取消停止后续，不自动重试或整体回滚。
5. 每台写后弹窗“请重新上下电”。人工声明和再次参数回读使用独立按钮，声明不证明供电状态。再次回读及版本适用性均通过后才记录 `post_power_verified=true` 并进入下一台。部分写入失败同样提醒；可记录人工声明，然后从独立读取入口重新核对，原失败回执保留，不重放写入。

请求只接受当前配对窗口租约及当前有效目标索引/模板编号。模板新值不可由执行员编辑。网关复用当前 reliability_v1 真人会话，发布权限由平台鉴权，配对与实例控制权由本机租约确定。模板查询不在控制心跳锁中执行；设备任务在后台线程运行，心跳独立。

## 响应关联及 Pn 限制

常规参数仅接受当前接口、精确标准 CAN ID、反馈类型与本次查询码一致的响应；一时仅一条请求，查询前排空旧流量，有界超时，无自动重试。整数按脚本大端和有符号/比例解释，保留十六进制原始响应。软件故障注入不证明真实厂商固件语义或持久化。

参考脚本的 `parse_pn_read_response` 虽接收参数编号，实际未核对编号；回包为 `FF FE 11 + u32`，没有编号回显。普通 `decode` 仍标 `association_unknown`，默认 `write_payload` 仍拒绝 Pn。新路径必须使用平台管理员发布的 v2 模板，固定 `protocol_profile=lro-pn-script-v1` 和已确认脚本来源 SHA256，绑定精确型号及 `raw_firmware/software/hardware/protocol`；不能推断任意108/109均适用。新模板需新编号/版本，旧模板及报告不改写。

用户已确认脚本参数表及其此前成功使用的经验，依据见 `PARAMETER_SCRIPT_OWNER_CONFIRMATION_20261030.md`。准备工具支持 `--script-compatible`，显式提供完整版本适用表和确认依据后生成待管理员审阅草稿；不调用发布接口。59项源参数不重复缩放，Pn 按32位无符号大端原始整数处理，不能套用串口16位定义。

已发布 v2 的 Pn 使用任务级会话：预检查为全部所选Pn接口打开被动接收通道并核对静默，不发送请求，避免第一项普通参数操作前漏掉竞争；每次请求前检查静默窗口，只保留一条在途请求，观察完整响应预算；报告明确 `association_method=single_flight_time_window`、`parameter_number_echoed=false`、请求号、原始请求/响应和时间。这个请求号是本机审计号，不是电机回显号。独立读取只发送查询，只有明确确认后的写入动作才发送 `C0 10 + Pn(u16) + value(u32)`；写后等待、独立 `C0 11` 查询并比较实际原始值。

超时、取消后不确定、重复回复（即使数值相同）、短报文、带标志的非标准ID、其他ID的Pn回复或其他客户端Pn请求，均停止本批后续操作，持久隔离整个接口。跨参数、跨电机、新任务及进程重启不能清除隔离；发送前写入 `in_flight` 标记，进程中断也会保留隔离。普通参数操作前后和终态也检查已打开的Pn通道，避免排队的迟到回复在收尾时被无声丢弃。

没有编号的协议无法从报文本身排除“旧回复恰好在后续请求的干净窗口内到达”。单请求、静默和隔离缩小并暴露可观察的不确定性，不能把时序关联写成编号校验或厂家保证。此模式依据已确认脚本显式启用，不自动放开旧模板。

## 生命周期、报告与恢复

参数/固件两类任务共用进程串行锁、网关维护锁和 backend 的所有者资源句柄，首版不跨总线并行。占用保持到终态报告保存及设备通道正常关闭成功，配置、扫描、使能、归零等会被拒绝。注销、更换账号、租约保护、断开和服务关闭取消并等待任务；超时或保存/关闭失败保留隔离，显式取消/关闭只重试收尾，不重放设备写入。

报告位于同一状态目录 `motor-parameters/<job_id>.json`。保留模板/来源哈希、实例状态目录、有效配置哈希、账号会话、目标、旧新值、原始响应、逐项写入状态、即时和再次回读、人工声明及错误。`not_written`、`send_uncertain_unverified`、`written_unverified`、`written_verified` 分别表示未写、发送结果不确定、已发未核验、即时回读已匹配；最后一项仍不等于重新上电后核验。进程重启把未完成任务标中断，不自动恢复写入。重新维护前先核对实际状态，独立读取，不根据旧成功字样重放。

重启恢复逐份处理仍标记 `active=true` 的任务，在该任务首次原子保存前，同时修正目标状态、逐项状态及计数。尚未发出的项标 `not_run`，发送边界处中断的项标 `send_uncertain_unverified`，原始响应、已写和已核验事实均保留。目录中有多份遗留任务时，每份都执行相同处理；恢复不创建工作线程、不查模板、不访问设备。已经结束或已在旧版本中标记中断的历史报告不重写，不能据新版本的修正反推旧报告已被纠正。

## Pn通道隔离后的恢复

Pn隔离记录保存在各窗口共用的报告状态根目录 `pn-quarantine/<接口哈希>.json`，不是按电机或参数单独隔离。停止参数任务并正常断开电机连接后，由用户显式“断开CAN”。仅在接口关闭反馈完整且全部 `up=false` 后，原记录追加归档至 `pn-quarantine/history/`，保留原因、时间和 `motor_power_cycle_detected=false`，才解除主机通道隔离。关闭失败、仍在线、缺少状态、任务未退出或归档失败时保留隔离；仅关闭socket、关闭软件或重启不解除。软件不自动断开CAN，不发电机复位/使能/供电指令。重新连接后重新独立读取；不要重放旧写入。

接口关闭确认只重建主机时序边界，不证明电机重新上电或所有设备端迟到回复已经消失。重连后仍需静默和无残留检查，人工重新上下电声明、即时回读与再次回读继续分开。
