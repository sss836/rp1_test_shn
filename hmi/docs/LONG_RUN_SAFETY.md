# 双工位长测第一批修复

本文件说明源码行为及验证边界。各系统构建状态以随包构建报告为准，尚未完成真实设备现场验收，不能据此宣称已解决实际设备的 8 小时故障。

## 操作员租约与客户端配套

网关租约默认 30 秒，可用 `--lease-timeout` 或 `RP1_FACTORY_LEASE_TIMEOUT_S` 配置。合法范围为有限值 `(0, 300]` 秒，启动参数优先于环境。`hmi/launch.py` 同样接收该参数并显式传给自己的网关，健康/状态快照的 `lease.timeout_s` 是生效值。

租约快照新增 `generation`、`revoked`、`quarantined` 和 `cleanup_error`。心跳须携带配置响应中当前的 `X-RP1-Lease-Generation`，过期裁决与撤销原子完成。撤销后的心跳不能自动认领，清理成功后也须明确重新配置连接。配置/快速准备属于显式认领。普通慢命令在同一命令锁内正常完成后可更新其自身租约，不能用心跳重新激活已撤销版本。

桌面心跳使用独立 Qt 网络对象，不占普通 REST 线程池。每窗口只有一个在途请求，正常周期 500 ms，截止定时器默认 500 ms，失败后 150 ms 重试。瞬时网络故障和 5xx 可重试；认证、协议或过期冲突停止自动续约。关闭窗口会取消在途请求和重试，旧版本的迟到结果丢弃。GUI 不响应时不会有后台线程代其无限续约；Qt 定时器自身也会受 GUI 事件循环延迟影响，此时最终由窗口租约处理失活。

**网关与全部桌面窗口必须配套更新。** 旧客户端的无 generation 心跳会被新网关拒绝，新客户端也不能对没有该字段的旧网关正常续约。该契约变更不支持混用版本。升级前仍须按仓库 AGENTS.md 核对真实停止/失能/PLC 总停止反馈，并正常关闭原实例，不能仅替换磁盘文件。

## 控制、记录与报告的时序

到点后控制线程只发出 `request_stop_sampling()`，冻结运动结束时间并交接位置保持。采集线程独占 CSV，自己处理停止、写完及 close。后台单 worker 等待记录关闭并确认结果，报告线程再继续分析。`stop()` 等待运动线程，不等待大文件关闭；`FactoryController.wait()` 保留等待运动及记录的便捷语义，针对运动交接可读 `playback.wait()`，针对记录可读 `playback.wait_recording()`。

记录状态分别提供 active、closing、finished 和 error。只有关闭及记录检查成功后 finished=true，当前 CSV 下载接口才允许读取。close 失败不会反向制造新的运动故障，仍会阻止报告和文件被误标为成功。运动中写失败或连续约 2 秒没有成功写入，则停止本工位并记录错误。

本地 HMI 显式使用 `local_only=True`，忽略录制器的旧 `TEST_PLATFORM_API_URL` 与 `INFLUXDB_TOKEN` 副作用，CSV 以排他创建方式打开，禁止覆盖已有原始测量。旧 CLI 默认模式继续保留原接口行为。工位在线状态、正式 CSV 核实/提交和平台审批仍使用各自现有流程，本次没有增加自动上传或自动审批。

`RP1_FACTORY_RECORD_RESERVE_BYTES` 默认 512 MiB，启动器允许传递该参数。记录开始前检查空间，采集中每 5 秒再检查；不足或写异常上报并停止本工位。该保留量仅为低水位，不等于完整 8 小时、报告复制和打包的容量预算。

## 独立控制监督

FactoryController 将所有成功的 `MotorBackend.command_mit()` 派发交给独立监督线程计时，覆盖保持、回放、暂停、手动和回默认使用的同一派发入口。阈值复用现有 `factory_hmi_faults.heartbeat_stale_seconds`，默认仍为 0.5 秒，没有跟随操作员租约放宽到 30 秒。驱动和 PLC 保护阈值未修改。

监督先锁存命令禁止标记和缓存故障、请求各运动线程停止，再尝试失能，不先查询硬件状态。重新使能后使用新的监督版本，旧回调不能失能新的运行。若 native SDK 长时间占住锁，软件可阻止它返回后的后续命令，但无法强行中断正在执行的 native 调用；真实失能仍依赖可用设备通道及驱动/PLC 保护，必须现场验证。Python 线程也不能保证进程被整体饿死时仍按硬实时期限运行。

## 清理失败与恢复

租约撤销后，单个清理任务按停止、失能、关闭电机连接、关闭本 owner 的 CAN 执行。每轮等待预算为 2 秒。异常或超时保留 lease 和 CAN 占用并标为 quarantine，不把软件所有权交给新窗口。正在运行的清理不会并发重试，超时不表示 native 调用已经取消。

确认设备状态并处理故障后，同一窗口身份可显式调用 `POST /api/v1/lease/recover` 重试清理，沿用本地网关操作员令牌校验。未完成或再次失败返回 409；全部 SDK 步骤成功返回后才释放该 owner 的接口，另一 owner 的接口不受影响。成功后仍须重新配置并显式使能，不自动恢复运动。此处 SDK 无异常返回不替代现场电机失能反馈。

## 本批之外仍需完成

- 报告的全量 CSV 读取、内存 tar/gzip 尚未改为流式，也未移出网关进程。
- 当前记录确认 worker 和清理任务仍在同一进程，未提供跨重启持久任务队列。
- PLC 日志/通信执行隔离、状态缓存与会话回收、半发布恢复、完整不可变 RunResult 及数据质量口径仍属后续范围。
- 300 MB 双路资源压力、8 h/24 h 稳定性、真实 SDK 失活及现场双工位验收尚未执行。

## 隔离检查入口

新增 `test_long_run_safety.py`、`test_lease_heartbeat_qt.py`、`test_long_run_gateway_asgi.py`。均使用假电机、mock PLC、合成文件和模拟网络回复，不控制真实设备。ASGI 检查为进程内路由/序列化测试，测试环境用 10 ms 调度脉冲驱动线程回调，不证明原生服务器唤醒、TCP 性能或真实网络行为。完整 pytest/HTTP 集成与现场运行需在具备完整开发依赖的候选环境继续验证。
