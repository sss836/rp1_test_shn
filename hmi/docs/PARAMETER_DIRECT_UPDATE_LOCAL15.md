# local15 参数直接更新与自动兼容审计

## 已实现：参数更新入口简化

local14 参数界面只允许 mode=read、模板一致、读取完整且有差异的任务生成写入预览。用户点击“只读参考”后会显示参考差异，但该结果是 mode=read_reference，模板列仍未加载，导致更新按钮禁用。现场已保存的 b5a80db87bdf4356a7888e84014a0c84 任务证实为 reference_checked_with_findings，7台电机均读回 V5.0.0.109 / 0.1.9 / 0.1.0 / 0.0.1.17。依据这些既有读回，纯离线模板查询可分别产生15、17、17、17、17、12、12项产线模板；不是缺少本机脚本。

`factory_hmi/desktop/motor_parameters_dialog.py` 新增直接更新编排：

- `update_selected` 允许已选目标从未读取、参考读取或旧比较结果直接发起；捕获工位配置、目标完整身份和账号来源。
- `_poll_update_versions` 使用现有版本读取异步接口，最多等待45秒，刷新真实身份；不使能电机。
- `_match_update_templates` 自动按当前型号/版本查询本机原产线脚本模板；保留仍适用的明确模板选择，不强行选择多个平台候选。
- `_read_update_parameters` 发起已有的只读比较，旧参考记录不会作为写入证据。后台任务继续使用既有参数读取超时与独占机制。
- `_continue_update` 在本次读取结束后确认所有所选目标均读全，跳过已符合目标的电机，生成差异电机写入清单。若任一所选台未读全则不继续，不静默缩小用户范围。
- `start` 仍展示一次实际目标与参数写入清单。用户确认后才进入原有写入任务；取消、请求失败、配置/账号/选择变化或关闭窗口立即终止自动编排。

请求在现有 REST 工作线程执行；Qt定时器只轮询读取进度。pending与流程阶段分别管理，重复点击不重复创建任务。每次成功回调结束后才进入下一步；失败回调解除准备状态。版本轮询有45秒预算；实际参数读写、维护锁、持久化和停止机制未修改。

参数入口部分只改变桌面编排；版本自动选择改动见下节。

## 已实现：108／109自动选择现有固定表

按用户最终指示，不动态读取或替换换算范围，不修改现有两张表数值。

- 新增 `factory_hmi/core/lro_fixed_profiles.py:fixed_profile`：完整版本108/109或有效数值版本0.1.8/0.1.9自动对应legacy/v1.03；数值版本核对原始0x1E回复。已确认的0.1.8无需再次人工确认。未知或相互冲突的版本不猜测。
- `core/backend.py`：默认模块不再因为读到109而拒绝使能；逐节点按版本选择现有SDK固定表。同一工位允许全108、全109或混装。已有显式身份配置继续核对，不悄悄覆盖。运行连接内版本改变时不热切表，断连后重新扫描。
- `core/controller.py`：使能反馈确认以实际选中的协议为准，不再只看旧配置的legacy默认值。
- 后端标零路径同样以实际协议选择；109仍使用现有“失能反馈—提交—待重新上电核验”路径。
- `scripts/log_motor_telemetry.py`：自动识别节点的CSV保留Iq电流、使能位及反馈头字段；108没有这些值时留空，109不丢列。不把Iq电流冒充力矩。
- 不修改原生驱动的legacy_limits/v103_limits两张固定表，也不修改产线参数值。参数按用户脚本更新；老化按选中的固定表运行。

新增测试覆盖全108七台、全109七台、混装、四型号配置、数值别名、未知及矛盾版本、109失能反馈、109标零和记录字段。全部使用fake设备。
