# MuJoCo 下垂收尾

## 功能及依据

按老板 2026-10-29 明确选择“直接用 mujoco 上的轨迹”，增加独立的 `mujoco_hanging` 收尾方式。左右 5/7 自由度手臂均可选用。原测试 NPZ 和既有已核实参数收尾继续保留，其他部位沿用原方式。

内置数据来自之前展示的 RP1.3.1 MuJoCo 运动学预览：`outputs/animal-office/mujoco-hanging-preview/frame-checks.json`。时间轴为 0—5 秒、61 个预览采样点；0—0.5 秒保持，随后 3 秒按原预览曲线转动肘部，再保持至 5 秒。左肘末值约 -1.410305586 rad，右肘约 +1.410305586 rad；其余关节为模型零位。5 自由度使用同模型前五个手臂关节，7 自由度保留额外两个腕关节的零位。

`resources/completion/mujoco_hanging.json` 保存四种关节顺序、完整采样点、模型范围、源模型文件 SHA256 和预览记录 SHA256。运行时无需安装 MuJoCo，不依赖原模型所在目录或网络。模型范围是模型资料，不能称为实机标定或线缆许可；系统不会据此自动给工位 YAML 写入 `verified=true` 或 `safe_to_disable=true`。

## 操作与运行过程

普通测试在老化运行卡片增加“结束后按 MuJoCo 轨迹下垂，再软件失能”。手臂应用配置后默认选用，开始前展示具体肘部目标、其他关节回模型零位、到位软件判据，并要求现场确认方向、零偏、安装、线缆及停放后撤力安全。取消确认不会开始测试。未选用则保留原有参数收尾或结束保持行为。

工厂模式的运行窗口提供同样的选择和独立确认。原有支撑/供电/物理急停确认仍保留；未确认模型姿态不能提交该方式。普通与工厂接口均校验严格布尔值；不能把字符串或数字当成现场确认。确认只表达操作员对本次所选轨迹的适用性确认，不产生设备实际失能反馈或 OTA 安装安全证明。

流程为：

1. 保留原轨迹实时预检、故障保护及测试记录。选择模型方式时，另在开始前检查末帧到收尾轨迹的接续是否在模型及已有本机限位内、是否满足已有速度和单帧步长限制。
2. 正常到时不开始新周期，补完当前整个周期；按循环次数及单次结束共用该收尾。测试 CSV 在末轮结束停止采样。
3. 从末位置接续到模型轨迹起点，再执行原模型下垂曲线。末位置和速度已等于模型起点时无需接续段；其他情况用位置/速度连续、终端速度为零的五次接续，按模型曲线速度与本机已有速度、帧步长约束校验。接续段可能增加总收尾时间。
4. 人工正常结束停止继续测试，尝试从当前命令位置/速度平滑接续。若该位置/速度无法生成受约束连接，则保持位置并报警，不因规划失败直接失能；不会假称已下垂或已完成。
5. 曲线结束后检查所有关节实际位置误差、实际速度及持续更新的反馈。到位误差不超过 0.03 rad、速度不超过 0.03 rad/s，连续稳定至少 1 秒才发送软件失能。这些数值是本功能明确展示的软件判据，不是新编的产品机械参数。
6. 全部收尾预算 30 秒。超时保持目标并报警，不因等待超时直接撤力。软件失能、急停、通信/电机故障及原有供电保护可中断；故障走既有保护。普通模式失能后保留连接；工厂模式确认正常收尾后才清理本窗口 CAN。

## 文件及调用关系

| 文件 | 修改内容与连接 |
| --- | --- |
| `factory_hmi/core/mujoco_completion.py` | 加载内置几何轨迹，检查适用部位与关节顺序，按实际 sign/zero_offset 映射电机坐标，规划接续并核对模型范围、本机限位、速度和单帧限制 |
| `factory_hmi/resources/completion/mujoco_hanging.json` | 四种手臂的不可变模型轨迹及源哈希，由包内源码清单覆盖 |
| `factory_hmi/models.py` | `PlaybackOptions` 增加本次收尾方式及确认标记，缺确认时拒绝所选模型方式 |
| `core/playback.py` | 预检收尾接续，执行模型曲线并以实际反馈判定到位稳定；异常接续保持、故障优先及异步本地留证 |
| `core/controller.py`、`core/service.py` | 把本次选项传到共用播放线程，不替换原 YAML 的机械标定或旧测试准入 |
| `gateway/schemas.py`、`gateway/app.py`、`gateway/quick_run.py` | 普通和工厂入口传递选项，工厂在供电/使能前验证模型接续；保持 CAN/租约，保留真实失败原因 |
| `client.py`、`desktop/app.py`、`desktop/quick_page.py` | 展示选项、目标与本次确认；旧方式仍可用，取消不发起测试 |

## 数据、线程和失败边界

版本及开始选项只走当前网关；平台角色及可靠性数据审批协议不变。原始测试 CSV 仍在本机，在测试结束时封存；回位及稳定不混入测试采样。模型来源、预设哈希、有效配置摘要、实际反馈、收尾时间、确认方式、超时和软件失能请求另写本地 `motion-completion/*.json`，不自动上传或补写已有封存数据。

运动仍由原播放控制线程负责；界面确认发生在提交前，REST 工作者提交后返回，普通轮询和工厂观察线程展示状态。模型数据缓存一次；接续在发出回位命令前检查。回位期间持续执行原反馈、诊断和心跳检查；没有安装证明签发、后台安装、强杀或锁文件删除。

## 验证及交付状态

检查使用四种实际内置测试 NPZ 与 FakeMotorBackend。虚拟时钟检查末轮完成、正常下垂、不到位、缓存反馈、非零速度、故障和保护取消；另有真实计时的假设备检查 5 秒曲线、稳定窗口及测试 CSV 分离。界面使用离屏 Qt、网关显式 mock PLC 与禁用 CAN，并检查普通/工厂协议的确认与参数传递。
