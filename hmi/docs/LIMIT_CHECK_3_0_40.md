# 3.0.40 限位检查和版本读取

## 现场症状和复现

以现场 3.0.39 和合并 CAN 诊断分支后的候选提交 `b0b73e7` 对照两份 11 月 26 日审查指导。五个核心文件（缺帧循环、版本查询、模块限位、搜索、收尾）在两个版本中相同。以下复现使用虚拟时间、七轴反馈替身和离线轨迹资源。

| 指导项 | 修改前复现或代码核对 | 本版处理 |
| --- | --- | --- |
| A、T　缺帧恢复 | 模拟电机仅在收命令后回复。仅 #7 漏掉第一条命令的回复时只发送一次，16 次读取重复组后在虚拟 153 ms 报超时。整组漏回也只点名 #1。 | 单节点、整组、总线长期静默、频繁丢帧均有独立测试。孤立丢帧可恢复，持续无回复触发原来的中止和失能流程。 |
| B、K　身份和力矩系数 | 已核实的 108 身份在下一次版本查询全超时后变成 timeout，旧原始响应和时间丢失。运动中也会启动下一轮查询。 | 读取仅由连接、使能前按需重查或失能时的手动请求触发。身份和 109 的 Kt 只绑定本次使能。 |
| E　异常定位 | 给 #2 注入报码 3、#7 注入报码 7，原代码只显示 #2。过期反馈还容易被现场当成当前驱动故障。 | 报错逐台给出总线、ID、关节及原因，标注异常台数。过期样本不当作新报码。限位报告记录缺帧轴、阶段、关节角、组间隔分布、GC 停顿和版本查询事件。 |
| F　CAN 发送和收帧时间 | 3.0.39 的相关 LRO 发送路径可能在异步写失败时仍被上层视为成功。 | 合入的诊断分支已将主机写入回执接入 LRO 单轴和组 MIT 及使能，反馈使用原生接收时刻。总线级长期收发计数增量属于指导的可选阶段，尚未实现。 |
| G　入口姿态 | 入场角超出参考角即拒绝，旧提示缺少关节和超出量。 | 默认继续按原参考角拒绝。工位可以显式设定入口余量，超限仍拒绝并显示关节、实测角、参考角及超出量。 |
| H、I　停稳 | 末轴每 25 ms 交替 ±0.00038 rad，原相邻帧速度达到 0.0304 rad/s，连续 5 秒留在收尾。撤去扰动后完成。准备和退让也缺少阻塞轴信息。 | 收尾按至少 0.2 s 时间窗估算速度，继续要求原有连续 1 秒停稳和角度跨度。界面和报告可显示阻塞轴及原因。 |
| C　GC | 采样会生成 Python 对象。现有证据无法判定现场 GC 是否造成过超时。 | 加入有界暂停记录用于与缺帧时间对照。大规模更改样本存储格式留待现场数据。 |
| D、J　处置策略 | 中止后走失能，实际结果可能未确认。左臂腕旋转负向和腕俯仰正向的独立复搜分支与整模块默认延伸搜索互斥。 | 中止报告保留失能请求和真实反馈。指导将中止方式和整模块腕部复搜列为另行决定事项。 |

## 控制流程与使用

`core/live_limit_probe.py` 的 `ProbeWorker` 在接受完整新反馈后才推进轨迹。等待缺帧期间允许重发最近一次成功发送的同一目标、同一增益。每个间隙最多 3 次，最小间隔为控制周期与 15 ms 的较大值。滚动 10 秒内已补询 20 次时，中止下一次补询。补询不延长 150 ms 反馈年龄或组间隔预算。交接、停止、异常反馈和过载仍按原保护路径处理。空读可能来自并发采样，报告将它与确实观察到的一整条总线的重复帧分开。具体保护响应时间仍受主机调度和原生写入耗时影响。

`core/motor_versions.py` 只有一个可取消读取线程，连接时先查一次，之后等待请求。待机和运动均无 60 秒定时器。单次通信超时可保留同一节点上一轮成功证据及原时间戳。有效身份发生变化、返回无效数据或读到无效 Kt 时，保留本次异常供检查。`core/backend.py` 在首条使能前确认读取线程已空闲，核对 180 秒内的版本身份，109 还需正值、身份匹配且在有效期内的实读 Kt。证据已过期时，该次点击仅安排读取并返回未使能，读取完成后需要再次点击使能。运动中的每条 109 力矩仍用实时 Iq 乘以本次锁定的 Kt。新收到的冲突、实时反馈超时、驱动报码及力矩门限仍可中止。整组成功失能、关闭连接和重新扫描均使绑定失效。待机时可手动读取。

`core/limit_block_check.py` 的 `Coordinates.decode` 汇总各轴反馈异常。有效码 7 按已确认的 legacy 或 V1.03 协议解释。`core/module_preflight.py`、`core/service.py` 和 `core/feedback_limit_search.py` 分别在位置边界、反馈检查和实际搜索行程异常时给出具体量。整模块报告仍原子写入本机原有位置。诊断读取失败也保留主报告。

`core/module_limit_check.py` 接受工位 YAML 设置 `factory_hmi.limit_check.entry_beyond_reference_margin_deg`，默认 0°，范围 0–10°。设置只作用于入口参考角，实际获准使用余量的关节写入 `entry_beyond_reference`。工装边界、关节和电机位置边界及轨迹预检继续执行。`core/limit_arm_completion.py` 保留原速度、跨度、停稳时间门限和保持目标行为。`desktop/pose_validation_view.py` 将阻塞关节和等待原因显示在现有提示区。

本版验证以隔离测试、模拟 CAN 写入和解包核对为依据。真实总线负载下的补询频率、机械停稳特性以及中止后机械支撑需由工位验收。各项模拟结果不用于判定现场某台样品损坏。本次发布的测试和下载回执另存于交付目录。
