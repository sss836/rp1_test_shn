# 助手查询与回答流程修复

实施范围：查询别名/过滤、重复检索处理、回答收尾、错误分类。保留6轮、120秒、费用预留及真实账号授权；本次不加入语义向量检索，也不更改上位机或设备控制。

## 修改

- `backend/app/services/assistant_parts.py`：规范化upper_body、UPPER、上肢等别名，保留ARM与UPPER的区别。
- `assistant_business.py`：实际应用用例/样品部位及类型过滤，先过滤再分页；支持用例启用、发布条件；不支持的条件明确报错。目录返回摘要、数量、实际过滤和下一页，详情按需读取。
- 用例查询的include_contexts读取当前账号可见计划关联计数，按普通计划上下文接口的关联及数据库权限取数，不代表远端已成功加载。诊断时通过原有版本化源码工具预取两个候选生成入口，附版本、行号和哈希，减少模型逐次找路径的开销；缺少快照时保留平台数据并明确规则未核验。
- `assistant_chat.py`：同任务的稳定目录/源码读取复用结果，复用前重新核对授权；实时状态和计划关联不缓存。重复证据不反复添加卡片，独立保留源码卡片。任务结果增加completion与termination_reason，仍以实际业务回执判断是否保存。
- `assistant_outcomes.py`：有限的公开错误类别和基于现有回执的部分结果，不返回供应商原始错误或凭据。
- `assistant/src/chat.mjs`：每轮告知剩余额度，第6轮实际禁用工具并整理已有结果；即使模型仍要求工具也不执行。等待实际结算结果，避免流正常结束时的异步清理误判成网络故障；用量未知仍停止新增调用并保留预留。
- `chat-errors.mjs`、`server.mjs`：将轮次/读取上限、总时限、单次模型超时、模型网络/HTTP错误、计费停止及授权失效分别传回后端，只记录固定原因和阶段元数据。
- `engineering.mjs`：区分普通知识、实时业务查询和源码排障；用例不可选先核对目录与计划关联，再核对源规则和现场加载。服务器事实与未读取的现场状态分开表述。
- `frontend/src/assistantApi.ts`、`components/AssistantPanel.tsx`：展示部分答复及准确的终止原因，保持实际保存回执独立显示。
- 查询单元测试、运行链路测试、原话官方模型专项、Pi SSE/异常测试和前端状态测试覆盖以上行为；隔离runner加入query-control检查入口。
