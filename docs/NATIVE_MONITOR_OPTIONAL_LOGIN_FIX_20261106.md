# 整机上位机顶部可选登录修正（0.4.1+platform.20261106.2）

## 问题与正确边界

用户明确要求与 `rp1-test-hmi` 的使用逻辑一致：最上方常驻登录栏，平台登录是可选能力，本地完整工作不需要先登录。

此前 `.1` 把平台登录误当成了本地启动条件。`desktop.py::_run_desktop()` 仅将本地启动接到 `first_authenticated`；`desktop_platform.py::start_initial_connection()` 要求有效平台会话，`open_local_workbench()` 又要求曾经登录，初始页面指向登录页。三处合在一起，未登录人员只能看本地只读历史，无法按原流程连接、测试和保存。这是本地工作与平台业务的边界划分错误，不是账号或网络故障。

修正版仅将平台上传、平台台账、核实送审及审批保留为登录后功能；本地原10个页面、SSH认证、设备条件检查、测试控制、记录、保存、导出仍遵守原实现，不使用平台角色替代设备认证。

## 数据、鉴权和恢复行为

未登录时仍按原流程在工位保存监控记录、工厂结果和CSV；不会自动向平台发送文件。当前登录账号、目标URL、数据域、文件哈希及人工声明在明确提交时冻结，后续重试继续绑定同一身份。登录并不补做此前没有明确提交的上传，也不自动批准原记录。

`NativePlatformService` 的中央入口及HTTP Cookie／CSRF鉴权未放开。未登录的setup、contexts、两域list／detail／submit／review、平台预览、研发源、tasks／retry仍拒绝，平台角色和服务器权限继续生效。原本地记录／导出使用原模块，不通过这些中央入口绕过审批。

平台服务或网络故障只影响平台操作，本地不因平台账号、会话到期或独立平台目录错误被禁用。当前取消仍是“请求取消”；服务端已经收到的提交须通过台账／回执核对，不承诺远端撤回。原有幂等、冻结SHA、审核revision、驳回重提和正式统计资格边界保持不变，未改变原数据库保存策略或审批规则。
